# 前端架构

Vue 3 + TypeScript + Vite + Element Plus + Pinia，仅面向 Windows 桌面（运行在 Wails WebView 中）。业务数据全程走 HTTP + SSE，系统能力走 Wails 绑定。

## 目录结构

```
frontend/src/src/
├── api/            HTTP 客户端、SSE 订阅（stream.ts）、契约版本（contract.ts）
├── chat/           流式与渲染纯逻辑：事件解码器、批渲染、消息合并、块解析、令牌解析
├── components/     视图与组件（chat/ dashboard/ memory/ workflow/ settings/ …，含 common/icons）
├── composables/    可复用组合式函数（主题、对话框、Toast、焦点模式、图表主题等）
├── i18n/           中英文词典与 t()
├── markdown/       Markdown 渲染配置（代码高亮、公式、图表）
├── router/         路由定义
├── stores/         Pinia（setup store），一个领域一个 store
├── types/          后端契约类型
├── utils/          时间格式化等纯工具
├── wb-ui.css       设计系统：令牌、原型组件样式（卡片 / 气泡 / 时间线 / 审批卡等）
├── themes.css      亮/暗主题变量
├── style.css       全局基础样式
└── assets/         前端静态资源
```

## 状态管理（Pinia）

按领域拆分，主要 store：

| store | 职责 |
|---|---|
| chat | 会话列表与当前会话、消息、流式状态（正文/思考/工具/用量/技能/产物）、发送与取消、审批、上下文占用、待办 |

| dashboard | 仪表盘统计与 token 趋势 |
| memory | 记忆中心三类记忆的浏览/搜索/写入/删除 |
| knowledge / tools / skills / mcp | 各自设置域的数据与操作 |
| workflow / cron / channel / pet | 对应功能页数据 |
| settings / provider | 全局设置与模型 Provider |
| theme / app | 主题与全局 UI 状态 |

约定：store 用 setup 语法，暴露 `ref` 与动作；组件不直接调 HTTP，统一经 store 或 `api/`。

## 与后端通信

- **HTTP**：统一客户端封装（基础地址来自 `app:ready` 事件的 `server_port`，或同步绑定取值），统一错误处理与 toast。
- **SSE**：`api/stream.ts` 负责建流（POST 建 run → EventSource 订阅）、事件名白名单映射、`Last-Event-ID` 重放、双看门狗（全静默 / 仅心跳）与指数退避重连；重连成功后拉一次权威快照补齐窗口。
- **契约版本**：前端持有契约版本常量，启动与 `GET /meta/contract` 比对，不一致显式报错而非静默失败。
- **Wails 绑定**：仅系统能力（文件对话框、剪贴板、窗口形态、托盘、本地图片代读）与 `app:*` 生命周期事件。

## 流式渲染管线

```
SSE 事件 → stream.ts 映射为领域事件 → ChatStreamDecoder 解码为「状态更新」
        → StreamEventBatcher 按帧批量合并 → chat store 落地
        → MessageBlocksRenderer 按块顺序渲染 → StreamingBubble 实时呈现
        → chat:done 后拉权威快照 → 切换到 MessageItem 历史回放
```

- 解码器与批量渲染是纯函数（有单元测试覆盖），把「事件流」与「组件渲染」解耦。
- 流式期与历史期共用同一套块序列模型（`chat/models/blocks.ts` + `chat/models/streamingBlocks.ts`），同一组件 `MessageBlocksRenderer.vue` 同时消费 `ResolvedBlock[]`（历史）与 `StreamingBlock[]`（流式），保证视觉一致。
- 历史消息与流式的边界由合并逻辑处理：乐观消息与权威快照按 seq / id 对账，避免重复或空消息覆盖已渲染内容。
- 消息列表重渲染有 CSS 级虚拟化（`content-visibility`），长会话滚动稳定。

## 块序列：单一真相源设计

`message_blocks` 表存的是按 seq 排序的稳定块序列：`thinking → tool_call → tool_result → artifact → skill → genui`，**不是**按维度分组。

- 后端：`service/chat.go:persistBlock` 按 `blockSeq++` 单调递增写 message_blocks（同一事件对应同一 seq）。
- 前端：`ChatStreamDecoder.decodeStreamEvent` 在每个事件分支同时产出：
  - 旧字段（`streamingContent / streamingThinking / streamingTools / streamingSkill`）——向后兼容 TaskTimeline 等老消费者。
  - 新字段（`streamingBlocks`）——`MessageBlocksRenderer` 直接消费的真相源；同类连续合并，连续正文 delta 累计。
- 流式收尾 `finalizeStreamingMessage` 把 `streamingBlocks` 转为 MessageBlock 形状写入消息（chat:done 先于落库完成的窗口期兜底）。

## 消息呈现

| 组件 | 职责 |
|---|---|
| MessageList | 滚动锚定、轮次分组（一条 user 开启一轮，组内紧凑、组间宽松）、空状态与示例提示、条目流、流式气泡、审批内联、终态横幅 |
| MessageItem | 单条历史消息：**过程默认展开**（与流式期观感一致，正文与工具按真实顺序穿插；过程 ≥2 步时给「收起过程」开关，用户点了才折成一行迹线）、内联 diff 卡、用量徽标、悬浮操作（复制/编辑/重生成/分叉/删除） |
| InlineDiffCard | 消息流内的文件变更卡：折叠态一行「动作 + 路径 + 增删行数」，展开懒加载 diff 并就地回滚 |
| StreamingBubble | 流式中的 MessageBlocksRenderer（按块顺序）+ 末条 text 的 MarkdownRenderer + 光标 + 实时用量 |
| MessageBlocksRenderer | 统一按块序列渲染（同时接受 ResolvedBlock[] 与 StreamingBlock[]）；text 块通过 slot 让外层接 MarkdownRenderer |
| TaskTimeline | 兼容旧数据降级路径（tool_calls_json 重建） |
| MarkdownRenderer | Markdown / 代码高亮 / 公式 / 图表渲染 |
| UsageBadge / ContextRing | 单条消息用量与当前会话上下文占用 |

## 记忆中心

`MemoryCenterView.vue` 四个分区：情景 / 语义 / 程序三类记忆，加**回写收件箱**。收件箱按状态展示 run 终局提炼的候选（事实 / 程序 / 技能草稿），逐条「合入」或「忽略」，并显示 pending / approved / rejected 计数。

## 桌宠窗口

`PetDesktop.vue` 渲染悬浮桌宠与迷你聊天面板。开启 `click_through` 后，组件采集可见元素（卡片 / 气泡 / 聊天面板）的包围盒并去抖上报，后端裁剪窗口可见区域，透明留白不拦截鼠标；聊天面板显隐、缩放、心情与窗口 resize 都触发重算。详见 doc/12。

## 右栏工作面板（Git）

`ChatView.vue` 的右栏除工作区 / 变更 / 任务 / 辅助对话外，接入 Git 工作面板 tab（header 图标组切换，组件与端点见 doc/07）：

| 面板 | 组件 | 数据流 |
|---|---|---|
| Git | `chat/GitPanel.vue` | `/git/overview` 首屏聚合；变更 / 历史 / 图谱三视图按需拉数（`/git/log`、`/git/commit`、`/git/commit/diff`、`/git/graph`）；分支切换 / 新建 / 删除、暂存 / 丢弃 / 提交走 POST 后回拉；工作区绑定变化自动重载 |

面板不建独立 store：直接经 `api/client` 取数，工作区与会话 id 取自 `stores/chat`；Git 面板随会话与工作区绑定变化自动重载。

## 应用外壳

`App.vue` 外壳只保留任务主链路，四个区域：

- **标题栏**（frameless 拖拽区）：应用标 + 当前任务名（设置页显示「设置」）+ 工作区 chip + 窗口控制。
- **顶栏横向菜单**（`AppNav.vue`，42px 导航条）：工作台 / 自动化 / 工作流 / 记忆 / 知识库 / 仪表盘 / 设置，激活态按顶层路由前缀与设置中心 `?tab=` 判定（未列入菜单的 tab 归「设置」）；右侧为命令面板（→ Ctrl+K）、明暗主题切换、新建任务。
- **极简左栏**（`--wb-side`；Ctrl+B 整栏收起）：
  - 快捷动作：新建任务（Ctrl+N）/ 搜索（Ctrl+K 开命令面板）/ 自动化（→ `/cron`）；
  - 任务列表（`SessionSidebar`）：分组（按时间）/ 平铺两种展示，条目单行「标题 + 相对时间」，根会话带分支数徽标，搜索框跨会话内容检索，批量删除入口图标化；
  - 底部：语言快切（中/EN）+ 设置入口。
- **主内容区**：RouterView，内含 `app-deco` 装饰层（左上青蓝冷光 + 右下品牌色暖光，`z-index:-1` 位于所有内容之下，两套主题都启用）。聊天（默认落地页）、自动化（cron）、设置三者直达。

功能页（模型 / 外观 / 通道 / 搜索 / 技能 / MCP / 工具 / 工作流 / 记忆 / 知识库 / 仓库导读 / 钩子 / 仪表盘 / 运行历史 / 任务中心 / 文件 / 文件夹 / 文档 / 桌宠 / 关于）全部收进设置中心：`SettingsView` 为「返回工作区 + 左侧三组导航（基础设置 / Agent 能力 / 数据与统计）+ 内容区」的全页布局，section 组件按需异步加载，`/settings?tab=x` 深链直达（组件 watch query 变化）。旧路由（`/memory` `/skills` …）在 router 里重定向到对应 section，命令面板与历史深链仍可达；独立窗口与子页除外（`/pet/desktop`、`/workflows/:id` 保留原路由）。

主题：玻璃拟态双主题，令牌唯一定义在 `themes.css`（`[data-theme='light'|'dark']` 两块）。

| 主题 | 基调 | 关键令牌 |
|---|---|---|
| light（默认） | 蓝调渐变 + 多处柔光晕 + 白玻璃卡 | `--wb-page-gradient`（三个径向光晕 + 线性渐变）、`--wb-surface: rgba(255,255,255,.74)`、`--wb-primary: #2f7bf6`、`--wb-grad-brand` 品牌渐变 |
| dark | 深紫底 + 紫罗兰玻璃 | `--wb-bg: #16121f`、`--wb-surface: rgba(43,35,66,.72)`、`--wb-primary: #8b5cf6`、`--wb-side: rgba(26,21,40,.80)` |

- **密度基线**（`style.css` 的 `:root`）：控件高 32px、控件字号 12.5px、控件圆角 10px；卡片内边距 18px、圆心半径 20px、内容区最大宽 1120px、区块间距 18px。宽松留白是这套视觉的基调，所有尺度取同一档而不是逐页微调。
- **玻璃参数**：`--wb-glass-blur`（20px）/ `--wb-glass-saturate` / `--wb-glass-border`（白色高光描边）/ `--wb-glass-inset`（顶部内高光），基元类 `.wb-glass` / `.wb-glass-solid` 是唯一定义处。
- **实底铁律**：`--wb-surface` 是半透明玻璃底，凡是「内容必须压在实底上才清晰」的场景（输入框 / 代码块 / 工具回执 / 弹层）一律用 `--wb-surface-solid`；Element Plus 的 `--el-bg-color`、`--el-bg-color-overlay` 已桥接到实底。
- **模糊分组**：只有最外层结构面（侧栏 / 顶栏 / 聊天头 / 输入区 / 各工作面板）加 `backdrop-filter`，卡内嵌套元素保持半透明——逐层模糊会成倍叠 GPU 开销而观感无差（收在 `wb-ui.css` 的「玻璃面组」规则）。
- **装饰层**：`.app-deco` 两团大面积柔光（左上青蓝 / 右下品牌色），两套主题都启用（`app-deco` 是玻璃透光层次的来源）。
- 图表配色走 `useWbChartTheme` 的蓝色梯度（主蓝 / 亮蓝 / 青绿）；KPI 数值与页面标题走 `--wb-grad-brand` 渐变字。

**图标体系**：全站唯一出口 `components/common/icons/index.ts`，统一到 lucide（24 viewBox 线性图标、round cap/join）。此前混用 Element Plus 图标（1024 viewBox 实体风格、光学重量偏沉）与自绘线性图标，两套语言在 16px 下笔画与圆角不一致，是「图标不齐」的根因。笔画重量由 `--wb-icon-stroke` 单点控制（亮底 1.7 / 暗底 1.85，抵消「亮底显粗、暗底显细」的视觉误差）；尺寸类 `.ic-xs / .ic-sm / .ic / .ic-lg / .ic-xl`，强调场景用 `.ic-strong`。对外命名沿用业务既有叫法，上游改名在出口做别名映射（`Code2` / `MoreHorizontal` / `Delete` / `Sunny`）。

**组件精修**：按钮（`.btn` / `.btn-primary` / `.btn-pill` / `.btn-soft` / `.btn-icon` 圆形图标钮）、输入（`.input` / `.input-pill` / `.input.with-icon`）、分段控件 `.seg`（胶囊轨道 + 白色滑块）、`.chip`、`.av`（圆角方块 + 淡蓝渐变 + 内高光）、聊天气泡与工具块圆角、`.ses-item` 与 `.appnav-item` 激活态（浅蓝强调条 / 品牌渐变实心胶囊）、`.kpi .c` hover 抬升。浮层统一收在 `style.css` 的 Element Plus 桥接段：弹窗 20px 圆角 + 遮罩模糊、下拉/提示/通知 14px 圆角 + 玻璃描边，菜单项胶囊化并按主色 hover。

### 两个必须知道的 CSS 层叠陷阱

1. **元素级 reset 必须用 `:where()`**。`wb-ui.css` 里的 `:where(.wb-ui) button { background: none; border: 0; color: inherit; font: inherit }` 若写成 `.wb-ui button`，特异性就是 (0,1,1)，**高于同文件任何单类组件规则 (0,1,0)** —— `.btn` / `.btn-primary` / `.send` 的底色、描边、文字色会全被这条 reset 吃掉，所有自绘按钮退化成「透明底 + 继承文字色」。组件内 scoped 样式因带 `[data-v-*]`（(0,2,0)）反而正常，于是表现为「有的按钮有色、有的没有」这种最难定位的形态。svg 的 `display: block` 同理（会压掉 utility 的 `inline`）。

2. **`v-html` 注入的 DOM 不带 `data-v-*`，scoped 里的子孙选择器全部失效**。`MarkdownRenderer.vue` 曾有一整块 scoped `.markdown-body pre/table/h1…` 规则从未生效过，实际生效的是 `style.css` 的全局同名规则 —— 两份定义、后写入的那份生效，改错地方不会有任何反馈。因此约定：**正文排版（标题/段落/列表/引用/表格/行内 code）唯一真相源是 `style.css` 的 `.markdown-body` 段；代码块与任务列表/脚注/公式占位等 v-html 相关样式放在 MarkdownRenderer 的非 scoped `<style>` 块**（该块已注明原因）。新增 Markdown 样式前先确认它属于哪一半。

后端 `settings/general` 未存过 theme 时回退 light，存过则尊重用户选择。主题本地缓存键为 `workbaby.theme.v3`。

## 关键约定

- 文案一律走 i18n（中英词典键对齐），不在组件内写死中文。
- 组件命名与目录按功能域归类；`common/icons` 统一图标出口。
- 焦点模式可隐藏思考与执行过程，只留结论。
- 设计系统集中在 `wb-ui.css` / `themes.css`：颜色、圆角、阴影一律用令牌，不散落硬编码色值。
