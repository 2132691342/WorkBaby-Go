# 05 · 工具系统

`internal/tool/`：统一 Tool 抽象、注册中心、JSON Schema 校验、风险五级与策略门、审批门与补充输入；执行调度在 `internal/harness/` 侧完成。工具是 Agent 的手，安全边界全部收口在这条链路上。

## 设计

- **单一接口 + 注册中心**：工具按名注册进 `Registry`（重名 4005）；注册即编译 Schema，坏 Schema 挡在启动期（`SelfCheckSchema` 全量复检）。启停状态不落 tool 层，由 service 结合 system_settings 决定哪些工具暴露给 LLM。
- **声明式元信息**：`ToolMeta`（可选 `MetaProvider` 接口）提供 ReadOnly / Destructive / PathParams / TimeoutSec / MaxResultChars / UIHint，权限裁决、只读并行、前端呈现统一由元数据驱动；未声明者按风险等级兜底推导。
- **纵深防御**：目录信任（前置）→ 工具策略门（SessionMode × 风险）→ 工具内部策略（如 exec 命令级白名单/危险正则）→ 审批门（阻塞等人）→ 停滞熔断 → 结果截断，各层互不替代。
- **边界**：`tool/` 不依赖 harness / agent / api / service / wails；`Approver` / `InputRequester` 抽象定义在 tool，实现位于 service 层，经 ctx 注入；工具自身不落库。

## 核心契约

### Tool 接口与结果

```go
type Tool interface {
    Name() string
    Description() string
    Schema() ToolSchema                       // Name/Description/Parameters(JSON Schema)
    RiskLevel() RiskLevel
    Execute(ctx context.Context, args json.RawMessage) ToolResult
}
```

`ToolResult`：Content（回填 LLM）/ Data（前端结构化展示）/ Err / Meta（耗时、exitCode 等）/ Refused（审批拒绝：非故障，不计失败熔断，模型可换路自愈）。

### 风险五级与策略门

| 风险 | 语义 |
|---|---|
| readonly | 读文件 / 检索 |
| write_local | 写本地文件 |
| exec | 执行命令 |
| network | 访问网络 |
| destructive | 删文件 / 删数据 |

策略门 `Gate`：显式规则（工具名，支持 glob，精确优先、最长 glob 次之）优先；无规则回退 `DefaultDecision`（SessionMode × 风险）：

| SessionMode \ 风险 | readonly | write_local | exec / network / destructive |
|---|---|---|---|
| default | allow | ask | ask |
| auto_edit | allow | allow | ask |
| yolo | allow | allow | allow |

决策枚举：`allow / ask / deny`；deny 时模型收到可见拒绝原因。

### 错误码（4000 段）

4001 二进制不在白名单 / 4002 命令命中拒绝正则 / 4003 需审批（或审批服务未配置、请求不存在）/ 4004 参数不符合 Schema / 4005 工具未注册、重名或已停用 / 4006 执行超时 / 4007 路径越出工作区 / 4008 结果超长被截断。

MCP server 的工具在连接就绪后动态注册进同一 Registry（停用/重载时注销），与内置工具共享同一条校验与策略链路。

## 关键流程

1. **注册**：`Register` 编译 Schema（jsonschema draft 2020-12，剥离 `$schema` 免联网拉元 schema）→ 入表；启动装配末尾 `SelfCheckSchema` 复检。
2. **执行侧管线**（harness `execOne`）：暴露校验（未暴露 → Refused）→ 注册表查找（未找到计失败）→ `ValidateArgs` 参数校验（失败回执 `invalid args`）→ 目录信任闸门 → 工具策略门（deny/ask）→ 停滞检测（同名同参连续达到上限 → 熔断回执）→ 幂等恢复（续跑命中 steps 快照直接复用）→ 执行（Meta 超时覆盖默认，panic 恢复）→ 结果截断（默认 50000 字符，`MaxResultChars` 可覆盖，尾部标 `... (truncated)`）。
3. **审批**：工具调 `Approver.Approve` 阻塞 → 落 `approval_records(pending)` → 发 `chat:approval` 事件 → 用户经 `/chat/approval/:id/decide` 回填。`needs_approval`（白名单外）批准过一次后进程内免审；`irreversible`（危险正则命中）每次都问；2 分钟未决按拒绝，取消随 run 终止。
4. **补充输入（request_input）**：模型缺关键信息时调用；`risk=input_required` 经同一审批通道暂停 run（kind=input），用户经 `/chat/approval/:id/answer` 回填，回复以「用户回复：…」回填模型。能力未注入时返回可见错误「未开启用户交互通道，请基于合理假设继续」，超时返回「用户未在限时内回复」，模型据此自行假设改道。

## 约束

- 审批等待全局 2 分钟上限：超时即拒绝，run 永不挂起。
- 只读并行：仅当一批调用全部 `AllReadOnly` 时并行执行，写类串行。
- 沙箱：文件类工具经 PathParams 做越界校验（4007），工作区根在启动时固定。
- 停滞熔断是兜底护栏：同名同参重复调用达到上限即终止本轮推进，防止模型死循环烧 token。
