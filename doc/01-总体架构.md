# 01 · 总体架构

WorkBaby：本地单用户的桌面个人 AI 助手（Windows）。数据保存在本机，不联网上传；gin 只绑定 127.0.0.1 回环 + 随机端口。强制条款（命名/错误/ID/测试）见 CLAUDE.md。

## 1. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言/桌面壳 | Go 1.25 + Wails v2 | 单 module；WebView2 渲染前端 |
| HTTP | gin | 业务 API + SSE 全走 HTTP |
| ORM/DB | GORM + glebarez/sqlite | pure-Go 无 CGO；WAL + FTS5 trigram |
| 配置 | Viper + system_settings KV | model.json / mcp.json 为配置真相源（DB 同步） |
| 前端 | Vue3 + TS + Vite + Element Plus + Pinia | Tailwind4 设计 token（--wb-*） |
| Agent | 自研 harness（ReAct 内核） | 见 doc/04 |
| LLM 适配 | 自研协议归一 | OpenAI / Anthropic / Ollama |
| 其他 | robfig/cron、expr-lang/expr、ulid、slog | 定时/工作流条件/ID/日志 |

## 2. 双主机架构

```
Vue3 前端（WebView2）
 ├─ fetch        → http://127.0.0.1:{port}/api/v1/**   REST（GET/POST，{code,message,data}）
 ├─ EventSource  → /api/v1/events?scope=&runId=         SSE 流式/推送
 ├─ Wails runtime→ 系统能力（文件对话框/剪贴板/托盘/窗口）
 └─ <img /files/**> → 受管静态文件（sprites/files/workspace）
```

- 端口注入：gin 监听 127.0.0.1:0，`app:ready` 携带 serverPort；前端 origin 由此建立。
- `/files/**` 双通道：Wails AssetServer 与 gin 同路由转发同一 FileServer，dev/生产行为一致。
- Wails 绑定只留系统能力；业务一律 HTTP（前端可独立于壳调试）。

## 3. 分层与依赖方向

```
internal/server ─→ internal/api ─→ internal/service ─→ 能力域（harness/llm/tool/capability/memory/rag/workflow/pet/…）
                                        │
                                        └─→ internal/repo ─→ internal/domain
                                              │
                                              └─→ internal/pkg（叶子工具包）
```

- server：gin 路由/中间件/SSE hub/统一响应；api：薄 handler（一文件一功能域）；service：编排与事务边界；repo：GORM；domain：单聚合根单文件（DO/DTO/REQ/VO/RESP/枚举/错误变量同居）。
- 能力域之间只经接口注入（tool.Delegator / tool.InputRequester / harness.Memory 等），互不感知实现。
- **能力接入契约（capability/）**：每个能力域以 Capability 三通道接入 Agent——Preload（每轮自动注入上下文）、Tools（模型主动调用）、Capture（run 结束后异步沉淀）。注册表按 order 串联 Preload，单能力失败仅降级不阻断 run；新增能力实现接口并注册一行，chat 装配代码不随能力增加而膨胀。已接入：人格、工作区、记忆（注入+memory_write+形成）、知识库（自动召回+knowledge_search）、Skill 触发、工作流（清单+run_workflow）。
- `scripts/check-boundaries.ps1` 门禁：domain-no-upward / repo-no-upward / service-no-http / server-no-downward / harness-no-http / pkg-no-internal。

## 4. 目录骨架

```
main.go / app.go            # 入口装配（embed 前端、单实例、托盘、启动序列）
internal/
  server/  api/  service/  repo/  domain/   # 四层 + 域模型
  harness/ llm/  tool/  skill/  mcp/         # Agent 内核与能力
  capability/                                # 能力接入：Preload/Tools/Capture 三通道统一契约
  memory/  rag/  workflow/  pet/             # 记忆/知识库/工作流/桌宠
  channel/ cron/  runtime/  config/  event/  # 通知/定时/内置运行时/配置/事件总线
  db/  pkg/  tray/  singleinstance/          # 迁移/叶子工具/系统托盘/单实例保护
frontend/  assets/（内置 skill·图标·字体）  build/  doc/
```

## 5. 事件总线与数据流

- `event.Bus`（发布订阅）+ `event.RunEventLog`（每 run 单调 seq 环形缓冲，SSE 断线重放）+ JSONL 文件 sink（无头导出）。
- harness 事件 → service 翻译 `chat:*` → Bus → SSEHub 按 scope+runId 过滤推送；桌宠/应用级事件 `pet:*`/`app:*` 同桥。
- 每次 LLM 调用一行 `token_usages`，仪表盘分线统计唯一数据源。

## 6. 存储语义

- DB 存元数据 + 内容；文件作配置源/快照/导出（model.json、mcp.json、sprites、snapshots）。
- `{home}`（用户目录 .workbaby 类）下：db / sprites / runs（事件 JSONL）/ runtimes（内置运行时）/ workspaces / snapshots。
- API Key / SMTP 密码 AES-GCM 加密，密钥首启随机生成。

## 7. 启动序列

单实例 Mutex+IPC → wails.Run → OnStartup：配置/DB 迁移/FTS5 → 装配 service 与工具注册表 → 审批排空 + streaming 遗留回收 + 内置 sprite 播种 → gin 启动（端口注入）→ 托盘创建 → 内置运行时后台解压 → app:ready。

## 8. 设计优势

- **Go 并发模型**：每 run 独立 goroutine + ctx 取消传播；CSP 事件总线解耦生产/消费；有界重试与停滞熔断防失控。
- **可靠性**：SSE seq 重放 + watchdog + 快照兜底；检查点 + StepRecords 幂等续跑；崩溃遗留启动回收。
- **上下文工程**：结构化摘要压缩 + 三层记忆 + token 计量全链路可见。
- **可扩展**：工具/Skill/MCP/Agent 定义均注册表化；能力经接口注入，单测可全 mock。
- **桌面体验**：桌宠与聊天同形象同状态；审批/补充输入内联；子 Agent 过程可视化。
