# 05 工具系统

## 定位

`internal/tool/` 定义工具接口、策略、审批风险语义；具体工具实现在 `internal/tool/<name>/`。harness 通过 `tool.Registry` 解析工具，`tool.Gate` 统一裁决。

## 设计要点

- **`Tool` 接口**：`Name / Description / RiskLevel / Schema / Execute(ctx, args) ToolResult`
- **风险等级**：`RiskReadOnly` / `RiskWriteLocal` / `RiskExec` / `RiskNetwork` / `RiskDestructive`
- **策略门（`tool.Gate`）**：`Allow/Ask/Deny` 三级 × `SessionMode`（restricted / default / auto_edit / yolo），glob 模式支持
- **审批风险常量**：`RiskApprovalNeeds`（可恢复命令，同名同 args 免审）· `RiskApprovalIrrev`（危险正则命中，每次必问）
- **per-call 风险上移**：工具实现可选 `RiskClassifier.ClassifyArgs(args) → (desc, risk)`；runner 的策略门据此给出精准审批描述与 risk
- **fail-closed 兜底**：脱链直调（测试 / 裸用）时工具内部仍走审批分支；runner 内调用由 ctx `GuardChain` 标记跳过
- **路径信任（`tool.PathTrust`）**：独立于策略门之外的目录三态（allow / ask / denied），祖先 allow 后代继承

## 核心契约

### `tool.RiskClassifier`（可选实现）

```go
type RiskClassifier interface {
    ClassifyArgs(args json.RawMessage) (description string, risk string)
}
```

- `description` 为空 → 工具无法按参数分类，回退工具级 `RiskLevel()`
- `description` 非空 + `risk == ""` → 白名单安全命令，runner 免审放行
- `description` 非空 + `risk ∈ {RiskApprovalNeeds, RiskApprovalIrrev}` → 走审批

### `tool.Gate.Decide(name, risk)`

| SessionMode | RiskReadOnly | RiskWriteLocal | RiskExec | RiskNetwork | RiskDestructive |
|---|---|---|---|---|---|
| `restricted` | Allow | Deny | Deny | Deny | Deny |
| `default` | Allow | Ask | Ask | Ask | Ask |
| `auto_edit` | Allow | Allow | Ask | Ask | Ask |
| `yolo` | Allow | Allow | Allow | Allow | Allow |

显式 `Gate.Set(name, decision)` 覆盖以上默认。

### `tool.Approver`

```go
type Approver interface {
    Approve(ctx context.Context, command string, risk string) bool
}
```

实现位于 service 层（`ApprovalService`），不感知事件总线。

### `tool.GuardChain` ctx 标记

```go
func WithGuardChain(ctx) context.Context   // runner 护栏链生效
func GuardChainActive(ctx) bool             // 工具内部据此跳过自有审批
```

## 关键流程

### 一次工具调用（统一护栏链）

```
runner.execOne(call):
  1. !exposed → refused("tool not exposed in this run")
  2. args schema invalid → ToolMessage("invalid args: ...")
  3. HasNestedToolCallMarker → refused("args contain nested tool-call markers (possible prompt injection)")
  4. trustTool(BeforeToolCall hook) → refused(...)
  5. gateTool(Gate.Decide):
       Deny → refused("denied by policy")
       Ask:
         desc, risk = RiskClassifier.ClassifyArgs(args) || (tool.Name(args), tool.RiskLevel())
         risk == "" → 免审放行
         Approver(ctx, desc, risk) → false 则 refused("denied by user")
  6. stagnation check（同名同参连续）→ refused("stagnation guard: ...")
  7. stepRecord hit → 复用结果（Resume 场景）
  8. execWithRecover(tool.Execute) → ToolResult
```

exec / skillrun 在 `Execute` 内部：
- 若 `GuardChainActive(ctx)` → 跳过自有审批（链内统一裁决）
- 否则若 `approver != nil` → 走审批；缺失时按 risk 类型直接拒绝（fail-closed）

### exec 命令分类

```go
policy.Classify(command+args):
  白名单 binary + 未命中危险正则 → ok=true, risk=""
  命中 DeniedPatterns → ok=false, risk=RiskApprovalIrrev
  白名单外                 → ok=false, risk=RiskApprovalNeeds
  空命令                   → ok=false, risk="" (Execute 硬拒绝)
```

## 约束

- 工具只读 / 写 / 执行的能力分级**仅用于策略门与风险提示**，不阻挡调用本身（除 Deny / 审批拒绝）
- 所有 `tool.Tool.Execute` 包了 panic recover（runner.execWithRecover）
- 工具结果 > `MaxToolResultLen` (50k 字符) 截断
- `file_*` 工具受 `WorkspaceRoot` 沙箱约束，路径越界立即拒绝（`ErrPathEscape`）
