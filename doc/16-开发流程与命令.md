# 16 · 开发流程与命令

日常开发、构建、验证、调试会用到的命令与操作指南。
工程规范以根目录 `CLAUDE.md` 为准；本文件只列命令与流程。

---

## 1. 初始化（一次性）

```bash
git clone <repo>
cd WorkBaby
cd frontend && npm install && cd ..
go mod tidy
wails doctor     # 一次性体检 Wails / Go / Node / WebView2
```

体检失败按 `wails doctor` 输出逐项修复（最常见：Go / Node 版本不符、WebView2 Runtime 未装、PATH 缺 Wails CLI）。

## 2. 日常开发

```bash
wails dev
```

- Go 改动自动重编译 + 重启 gin server；
- 前端改动 Vite HMR；
- DevTools：开发模式下 WebView2 中按 `F12`；
- 桌面壳与后端共享同一端口：业务 API `http://127.0.0.1:{serverPort}/api/v1/**`、事件 `http://127.0.0.1:{serverPort}/api/v1/events`（SSE）。端口由后端启动时随机分配，`app:ready` 事件注入前端。

## 3. 单独验证

```bash
go build ./...
go test ./...                                 # 全部测试
go test -short ./...                           # 跳过依赖外网的用例

cd frontend
npm run typecheck                              # vue-tsc --noEmit
npm run build                                  # 先有 dist/，否则 Go embed 编译失败
npm run lint                                   # 项目级 lint
```

架构边界（依赖方向 / internal/pkg 叶子工具与业务分层 / service 不引入 HTTP 等）由脚本门禁：

```bash
powershell -ExecutionPolicy Bypass -File scripts/check-boundaries.ps1
```

提交前应至少跑通 `go build`、`go test`、`frontend typecheck`、`frontend build`、`check-boundaries`。

## 4. 前端单独运行（无 Wails 壳）

用于纯前端调试（仅 layout / store / router，不验证完整双主机通信）：

```bash
cd frontend
npm install
npm run dev      # 默认 :5173；需在浏览器 devtools 手填 localStorage('wb.serverPort') 指向已起的后端
```

纯 dev 模式下 `bootstrapServer()` 会按 `Wails 事件 → localStorage → 报错` 的顺序降级；详见 `frontend/src/src/api/bootstrap.ts`。

## 5. 调试要点

| 现象 | 检查 |
|---|---|
| 前端拿不到 serverPort | `app.go` 中 `EmitReady` 是否在 `OnDomReady` 之后被调用；前端 `EventsOn('app:ready')` 注册时机 |
| API 404 | 前端 `api/http.ts` 的 origin 拼接（必须含 `/api/v1`）；后端 `internal/server/router.go` 路由前缀 |
| SSE 断连 | `event.Bus` 心跳；前端 `EventSource` 自动重连机制；runId 过滤是否正确 |
| SQLite locked | 默认开 WAL + busy_timeout=5000；并发写多发于多 run 同时落 checkpoint |
| 启动白屏 | DevTools console；前端 `booting/bootError` 状态；`dist/` 是否嵌入 |
| 打包缺运行时 | `build/bin/runtimes/` 是否有内容；`scripts/copy-runtimes.ps1` 是否执行 |
| WebView2 报缺 | `wails doctor`；Win10 1903 以下需 `wails build -webview2 download` 或 `-webview2 embed` |

## 6. 提交与分支

- 主分支：`main`（生产可发布）。
- 功能分支：`feat/<scope>`、`fix/<scope>`、`docs/<scope>`，从最新 `main` 派生。
- Commit 信息用 `<scope>: <imperative summary>` 格式（例：`chat: dedupe RunDone on stream end`），含场景与根因；不允许空泛描述。
- PR 标题与 commit 一致；正文需要包含「现象 / 根因 / 修复 / 验证」四节。
