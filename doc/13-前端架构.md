# 13 前端架构

## 定位

`frontend/` Vue 3 + TypeScript + Vite + Element Plus + Tailwind CSS v4（Wails 嵌入）。通过双主机与后端通信：业务 API 走 gin HTTP，流式事件走 SSE。

## 设计要点

- **双主机通信**：所有业务调用走 `apiGet` / `apiPost`（`src/api/client.ts`），端口来自 `wb.serverPort` localStorage；事件订阅走 SSE；外部链接 / 文件对话框走 Wails 绑定
- **聊天为核心**：左右双栏（侧栏 + 聊天主区），消息流用 `MessageList` 流式渲染（节流 + 虚拟滚动窗口）
- **工具调用紧凑卡片化**：工具作为单行摘要卡片（图标 + 工具名 + 参数要点 + 耗时），点击展开详情；错误态常显红色左缘
- **思考面板**：流式中自动展开 + 自动滚底 + Body 图标 + chevron，正文开始产出后自动折叠
- **i18n 自研轻量方案**：避免引入 vue-i18n；`t('key')` + 字典完整性测试防线（自动扫描源码 key 缺失）
- **设计 token**：`themes.css` 的 `--wb-*` 变量（亮/暗两套），Tailwind v4 CSS-first 配置（`style.css @theme` 同步 `--color-wb-*`）

### 关键 store：`useChatStore`（`stores/chat.ts`）

| state | 用途 |
|---|---|
| `sessions` / `currentID` | 会话列表与当前 |
| `messages` | 当前会话快照（来自 replace:true 的权威快照） |
| `streaming` / `streamingContent` / `streamingThinking` / `streamingTools` | 流式状态（独立气泡） |
| `streamingStats` | 本轮 token 统计（前端展示上下文占比用此值） |
| `todoState` | 计划卡 |
| `fileChanges` | 文件变更 |
| `error` / `stopReason` / `pendingApproval` | 错误/终态/审批 |

**关键不变式**：
- `currentID` 一旦设置，`messages` 总是该会话的最新快照
- `streaming===true` 时 SSE 监听中，UI 显示 `streamingContent/streamingTools`
- SSE 断流后 `safeLoadMessages({replace:true})` 拉权威数据

### SSE 处理（`api/stream.ts`）

`mapSSEEvent(name, data)` 归一化为内部 `ChatStreamEvent`（`content / thinking / stats / tool_call / tool_result / approval_decided / stopped / error / gap`），前端不直接消费 SSE 名。

可靠性规则：

- **首连即重放**：首次连接带 `last_event_id=0`，服务端补发该 run 已缓存的全部事件（POST 返回到 SSE 握手之间发出的事件不丢）
- **仅 chat:done 是终态**：`chat:error` 可能是非致命错误（run 会继续并最终补发 done），提前断流会丢后续增量；另有 15 分钟总超时兜底强制收束（后端 run 墙钟 10 分钟 + 余量）
- **工具耗时**：`chat:tool-result` 的 `duration_ms` 优先采用后端真实计量（本地 started_at 差值会把审批等待算进去）
- **watchdog 75s + 手动重连**：超过 2× 心跳周期无事件 → 主动断开 → 指数退避重连；重连成功后（`sse-ready`）回调 `onReconnect` 让 store 拉权威快照兜底重放窗口
- **工作流页面**：独立订阅 `scope=workflow&runId={executionID}` 的 SSE，节点级事件实时刷新详情；Wails 事件桥仅桥接 `app:*`

### 流式气泡 `StreamingBubble.vue`

| 区块 | 行为 |
|---|---|
| 限流重试提示 | `chat:retry` 触发展示 |

## 关键流程

### 一次聊天 send 端到端

```
ChatInput → chat.sendMessage(text)
  → POST /api/v1/chat/stream → {run_id, session_id, assistant_msg_id}
  → streamChat({run_id, ...}) SSE
    → onEvent → batcher.push
    → batcher flush (rAF / 32ms / 终态)
      → applyStreamUpdate(streamingContent/Thinking/Tools/Stats/...)
      → setStopReason → streaming=false → safeLoadMessages(replace:true)
  → finalizeStreamingMessage（仅在权威快照缺失本 run 回复时补占位）
```

### Markdown 渲染管线

```
MarkdownRenderer.render(content)
  → stripThinkTags(content)              ← 防兼容端点把 </think> 塞进正文
  → md.render → DOMPurify.sanitize
  → bodyRef.addEventListener(click, ...)  ← 委托：链接交系统浏览器、代码复制
enhance (终态一次性):
  → enhanceMarkdown: katex + mermaid 异步
  → decorateCodeBlocks: 长代码折叠 + 复制按钮
```

### 工具调用展示（`TaskTimeline.vue`）

- 每条工具 = 单行卡片：状态图标 + 工具图标 + 工具名 + **行内参数摘要**（从 args JSON 抽最有信息量字段如 path/command）+ 耗时；hover 显示复制/重试
- 点击整行展开 args + result（diff 高亮 / 错误红调）；chevron 旋转
- 错误卡常显红色左缘 + 自动展开
- 头部 "执行过程 · N" + 计数 + 展开/收起全部

## 约束

- 链接一律拦截交系统浏览器（`openExternal` / `BrowserOpenURL`）—— 严禁 WebView 内导航（会让整个 SPA 被替换为 502 错误页）
- 工具消息 (`role=tool`) 不下发到 UI（`toUiMessages` 过滤），仅供 LLM 上下文重建
- SSE 消息 ≤ 100 条/秒 → rAF 批渲染；终态立即 flush
- 字典 key 缺失会被 `i18n/__tests__/dict.spec.ts` 自动拦截（防空跑守卫 + 完整性 + 回退检测）
