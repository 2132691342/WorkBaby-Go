# WorkBaby 项目概览

## 定位

WorkBaby 是运行在 Windows 桌面端的个人 AI 助手。它不是网页套壳：后端是一个完整的 Go 应用，Agent 可在用户本机真实调用工具（读写文件、执行命令、跑脚本、联网检索、访问外部 MCP 工具源），并把全部过程数据（记忆、快照、产出物、运行事件）收拢在自己的目录体系里。所有数据落本机，不依赖任何云端账号体系；单用户、本地优先。

- 目标用户：在 Windows 桌面常驻一个能真正干活的 AI 助手的个人开发者与办公用户。
- 核心场景：多轮对话 + 工具执行（写代码、跑命令、分析文档）、本地知识库问答、技能包自动化、可视化工作流与定时任务、桌宠陪伴。

## 能力清单

| 模块 | 能力 | 入口文件 |
|---|---|---|
| 对话 | 多会话、流式回复、思维链分离、中途插话（steer）、检查点续跑、断线重连 | `internal/service/chat.go`、`internal/api/api_chat.go` |
| 工具执行 | 文件读写编辑、命令执行、网页抓取、搜索、HTTP、纯函数、文档解析、归档 | `internal/harness/runner.go`、`internal/tool/` |
| 记忆 | 情景 / 语义 / 程序三类记忆 + 长期 `MEMORY.md` + 跨会话召回 | `internal/memory/`、`internal/capability/memory.go` |
| 知识库 RAG | 本地文档导入 → 分块 → FTS5 检索 → 注入上下文 | `internal/rag/`、`internal/service/knowledge.go` |
| 技能 | `SKILL.md` 协议技能包（说明 + 允许工具 + 可执行脚本），按输入自动匹配 | `internal/skill/`、`internal/service/skill.go` |
| MCP | 外部 MCP server 作为工具源，stdio 子进程托管，可热重载 | `internal/mcp/`、`internal/service/mcp.go` |
| 工作流 | 可视化 DAG：LLM / 工具 / 代码 / 条件 / HTTP / 人工输入 / 通知，共七类节点 | `internal/workflow/`、`internal/service/workflow.go` |
| 定时任务 | cron 驱动工作流，动作经 `run_workflow` 派发 | `internal/cron/` |
| 后台任务 | 有界 worker pool 异步执行长任务，任务中心看进度与结果 | `internal/service/task.go` |
| 通知通道 | email(SMTP) / webhook / console + 发送日志 | `internal/channel/` |
| 文件变更与产出物 | 写前快照 + diff + 回滚；产出物登记、经 `/files` 预览 | `internal/service/file_change.go`、`internal/service/artifact.go` |
| 工作区 | 会话绑定外部目录 + 沙箱面板 + 目录信任三态 | `internal/service/workspace.go`、`internal/service/trust.go` |
| 桌宠 | 独立置顶小窗形态 + 聊天页悬浮体，形象可裁剪，状态机由 run 事件驱动 | `internal/pet/` |
| 可观测 | token 用量（含缓存 / 委派 / 压缩）、执行记录、run 事件 JSONL 导出、仪表盘 | `internal/service/dashboard.go`、`internal/event/runlog.go` |

## 目录结构

```
main.go / app.go / wails.json / go.mod   装配入口与构建配置
assets/      应用图标等静态资源
build/       Wails 打包产物与平台配置
doc/         项目文档
frontend/    前端工程（Vue3 + TS + Vite）
internal/    Go 后端全部代码（24 个包）
runtimes/    随包内置运行时（Node / Python / PowerShell 等）
scripts/     构建 / 门禁 / 打包脚本
```

| rag/ | FTS5 检索与索引 |

## 数据根目录与工作区沙箱

数据根 `{home}`：优先环境变量 `WORKBABY_HOME`，否则 `%APPDATA%/WorkBaby`（`internal/runtime/paths.go`）。

| 路径 | 用途 |
|---|---|
| `{home}/db/workbaby.db` | SQLite 主库（WAL） |
| `{home}/logs/` | 日志 |
| `{home}/config.yaml` | 主配置（含 masterKeyB64，首启自动生成落盘） |
| `{home}/runs/` | run 事件 JSONL 导出（每 run 一文件，保留最近 50） |
| `{home}/workspace/` | 全局默认工作区 |
| `{home}/workspaces/{sessionID}/` | 未绑定会话的隔离工作区 |
| `{home}/knowledge/` | 知识库导入的受管文件 |
| `{home}/memory/{sessionID}/MEMORY.md` | 会话长期记忆（未绑定时） |
| `{home}/snapshots/{sessionID}/` | 写前快照（未绑定时） |
| `{home}/skills/` | 全局技能目录 |
| `{home}/sprites/` | 桌宠形象资产 |
| `{home}/files/` | 受管文件（经 `/files` 预览） |
| `{home}/runtimes/` | 内置运行时解压目录 |
| `{home}/model.json`、`{home}/mcp.json` | 配置文件为源（存在则同步入库） |

工作区沙箱：会话绑定外部目录后，过程数据统一收进 `<workspace>/.workbaby/`，工作区根视为只读输入源。子目录约定（`internal/runtime/sandbox.go`）：

| 子目录 | 用途 |
|---|---|
| `.workbaby/memory/` | 会话长期记忆（按 sessionID 分目录） |
| `.workbaby/snapshots/` | 文件写前快照（可回滚） |
| `.workbaby/scripts/` | 本工作区复用的过程脚本 |
| `.workbaby/output/` | 产出物（报告 / 导出 / 生成文件） |
| `.workbaby/cache/` | 派生缓存（可重建） |
| `.workbaby/tmp/` | 执行期临时文件 |
| `.workbaby/skills/` | 本工作区技能目录（同名覆盖全局技能） |

沙箱在「绑定工作区那一刻」由 `Ensure()` 建立，并写入 `.gitignore`（内容 `*`）使整棵沙箱树对 Git 不可见。

## 设计优势（现状结论）

1. **无 CGO 单文件分发**：SQLite 走 pure-Go 驱动（glebarez/sqlite），构建链不依赖本地 C 工具链。
2. **双主机 HTTP+SSE 与 Wails 桥接**：业务 API 走 gin HTTP（`127.0.0.1` 随机端口），系统能力（文件对话框 / 剪贴板 / 托盘 / 窗口形态 / 本地图片代读）走 Wails 绑定；前端与业务后端解耦，可独立开发与测试。
3. **统一执行平面**：chat、工作流、后台任务、子 Agent 委派都登记到同一 `ExecutionRegistry`，共用一套 run 拓扑与 `chat:*` / `task:*` / `workflow:*` 事件命名。
4. **自研内核可完全掌控上下文与护栏**：能力注册表按序装配 system 段；压缩器、工具定义预算、停滞熔断、循环上限、计划模式硬拦、目录信任、反幻觉核验全部落在内核内，可裁剪、可观测。
5. **SQLite 单写者与 WAL**：连接池收敛为单连接（`SetMaxOpenConns(1)`）保证写入串行与 seq 一致；WAL 日志 + `busy_timeout` + 外键约束。
6. **FTS5 trigram 中文检索**：记忆与知识库的 FTS5 虚拟表统一 `tokenize='trigram'`，中文按 3 字符窗口切分，避免整句退化为单 token 导致检索失效。
7. **事件可重放**：每条 run 事件带进程内单调 `seq`，SSE 断线以 `Last-Event-ID` 从内存环形缓冲重放；缓冲覆盖不到时下发 `chat:gap` 由前端转全量回补。
