# 聊天与会话

位置：`internal/service/chat.go`（编排）+ `internal/harness`（执行）+ 前端聊天管线。

## 会话

一条会话携带：模型（provider + model 名）、采样参数覆盖、权限档、工作区路径、上下文预算、记忆开关。

- 三层参数合并：provider 默认 → 会话显式覆盖 → 请求级覆盖（temperature / thinking_effort），生效快照通过 `/chat/sessions/:id/params` 下发，前端输入框 chip 展示。
- 会话创建即可绑定外部工作区（校验目录存在 + 登记信任 + 建立 `.workbaby` 沙箱）。
- 会话操作：重命名 / 切模型 / 切权限 / 清空消息 / 分叉 / 批量删除。

## 一次对话的完整链路

```
前端 POST /chat/stream ──► 创建 assistant 占位消息，run 在 goroutine 开跑，返回 run_id
前端 GET  /events?scope=chat&runId=… ──► SSE 消费事件
run 内部：
  buildSystem      能力注册表按序注入（人格→环境→工作区→计划→记忆→知识库→技能→工作流）
  harness.Runner   ReAct 循环（工具调用 / 压缩 / 闸门）
  事件回传         chat:skill / chat:stream / chat:thinking / chat:tool / chat:tool-result / chat:stats / …
run 结束：
  消息落库（content / thinking / tool_calls / 用量 / stop_reason）
  用量明细落 token_usages
  能力 CaptureAll（记忆沉淀等，异步、独立超时）
  chat:done 终态事件 → 前端拉权威快照替换流式气泡
```

关键点：**流式气泡只是视图，终态以权威快照为准**。`chat:done` 后前端立即拉取消息列表替换流式内容，消除「流式 + 权威」重影窗口。

## 前端流式管线

`api/stream.ts` → `ChatStreamDecoder`（纯函数，事件 → 状态更新）→ `StreamEventBatcher`（一帧一渲染）→ store refs → 组件。

- 事件白名单 + 解码与渲染分离，解码器有单测覆盖。
- 断线重连：指数退避（500ms→8s）+ 具名心跳（30s）驱动的 watchdog（区分「空闲」与「假死」）+ run 总超时兜底。
- 历史回放：工具调用 / 结果落 `message_blocks`，刷新或切会话后完整还原过程时间线。

## 中途交互

| 能力 | 入口 | 行为 |
|---|---|---|
| 插话（steer） | 输入框发送 | 不打断当前 run，下一轮前注入 |
| 排队 | 流式中发送 | 入队，run 结束自动 flush |
| 停止 | 停止按钮 | run 取消；仍在 running 的工具立即落 `stopped` 终态 |
| 续跑 | 中断消息「继续」 | `Resume` 从检查点继续 |
| 补充输入 | `request_input` 工具 | run 暂停，前端弹输入卡，回复后续跑 |
| 审批 | 审批门 | 内联卡片批准 / 拒绝 / 跳过 |

## 上下文占用

`/chat/sessions/:id/usage/context` 与 run 用同一套 `buildSystem` 装配，返回分段占用（system / 历史 / 工具定义 / 记忆 / 知识库）。前端画成环形进度，超预算阈值时提示可压缩。手动 `/compact` 支持附加保留指示与保留窗口，归档摘要写入会话 meta 并钉入上下文。
