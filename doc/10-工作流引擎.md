# 10 工作流引擎

## 定位

`internal/workflow/` 实现 DAG 工作流：用户编排节点图 → 触发执行 → 节点按依赖/并行层/超时运行。可被 agent（`run_workflow` 工具）或 cron 触发。

## 设计要点

- **图 = 节点 + 边**：`Node{ID, Type, Params, DependsOn[]}`；DAG 校验（环检测）放 graph 层
- **并行层**：同层节点并发跑；层间串行；用时间区间交集判定并行而非墙钟（更稳）
- **节点类型**：`llm`（LLM ReAct 子循环）/ `tool`（直接调工具）/ `condition` / `http` / `code` / `human_input` / `channel` / `input` / `output` / `loop`
- **执行寄存器**：可被 agent 复用（避免重复启动同一 workflow 实例）
- **取消真正打断**：ctx 取消 → runner 检查 → 已发起的 goroutine 收到信号 → 节点返回 cancelled；最终状态 cancelled 而非 failed

## 核心契约

### WorkflowDO

| 字段 | 说明 |
|---|---|
| `id` | ULID `WORKFLOW_` |
| `name` / `description` | 用户命名 |
| `definition` | `[]Node` JSON |
| `enabled` | 是否可触发 |
| `created_at` / `updated_at` | 毫秒 |

### WorkflowExecutionDO

| 字段 | 说明 |
|---|---|
| `id` | ULID `WEXEC_` |
| `workflow_id` | 关联 |
| `state` | `pending` / `running` / `completed` / `failed` / `cancelled` |
| `started_at` / `finished_at` | 毫秒 |
| `node_results` | `{node_id: {status, output, error, started_at, finished_at}}` JSON |

### 节点类型契约

```go
type Node struct {
    ID         string                 `json:"id"`
    Type       string                 `json:"type"`  // llm/tool/condition/...
    Params     map[string]any         `json:"params"`
    DependsOn  []string               `json:"depends_on"`
    TimeoutMs  int                    `json:"timeout_ms,omitempty"`
}
```

## 关键流程

### 并行层执行

```
level = topological_layers(nodes)
for each level:
  parallel:
    for node in level:
      go runNode(ctx, node, inputs from prior levels)
  wait all
  if any failed: cancel remaining level → state=failed
```

### LLM 节点

`llm` 节点复用 agent harness 的 `WorkflowReactor`（独立 runner，工具白名单 = workflow 自带的 tools）：复用 ReAct 主循环、超时、checkpoint。

### 取消语义

```
Cancel(workflowID) → cancelRoot(ctx)
  → 节点 goroutine 收到 ctx.Done() → 返回 cancelled
  → Executor 收束 → state=cancelled（不计入 failed）
```

## 约束

- 入参图必须无环（`graph.Validate`）；有环 → 注册失败
- 节点 ID 在图内唯一；`DependsOn` 引用必须存在
- 节点超时独立于 workflow 总超时；超时报错但不打断兄弟节点
- `human_input` 节点暂停整个 workflow 等人工回复（类似 MCP `request_input`）
