# 08 记忆系统

## 定位

`internal/memory/` 实现三层记忆：**长期 delta**（memory_episodes 情景）/ **语义 fact**（memory_facts）/ **程序 procedure**（memory_procedures）。会话短期上下文不属于记忆层——由 chat.toLLMMessages 唯一负责（工具配对、孤儿剥离、占位清理）。

## 设计要点

- **三层各司其职**：长期 delta = 跨会话可检索的事件摘要；语义/程序 = 结构化知识与工具链模板（"用户偏好简洁回答" / "工具流程：websearch→file_write"）；形成策略为确定性打分，不调 LLM
- **长期 MEMORY.md**（`long_term.go`）：每会话一份追加式文件（落点跟随会话工作区 `{dir}/.workbaby/memory/{sessionID}/MEMORY.md`），容量超限保护（100KB）；memory 能力每轮把尾部注入 system
- **FTS5 检索**：episodes / facts 各建 trigram 虚拟表；短查询与零命中走子串扫描兜底（与知识库共用 pkg.SplitTokens 切词口径）
- **写入路径**：`memory_write` 工具（模型主动）/ `CaptureAll` 自动形成（run 结束异步、独立超时）

## 核心契约

### 数据库表

| 表 | 关键列 | 说明 |
|---|---|---|
| `memory_episodes` | `session_id, summary, transcript, score, triggers` + FTS5 | 情景记忆（每条含对话原文快照） |
| `memory_facts` | `(subject, key)` 唯一 · `value, confidence, source` | 语义记忆（同 key 覆盖）；source 记来源会话 ID |
| `memory_procedures` | `name` 唯一 · `steps(JSON), last_used_at` | 程序记忆（工具链模板） |

### Formation 触发器（formation.go，确定性打分）

基础分 0.15（存在分 + 对话长度）；Episodic 阈值 0.30——基础分单独不够，必须有触发器加分才沉淀情景，杜绝每轮都落一条的噪音。

| 触发器 | 命中条件 | 加分 |
|---|---|---|
| EXPLICIT_REMEMBER | 「记住 / 记得 / remember」 | 0.55 |
| PREFERENCE_DETECTED | 「我喜欢 / 我偏好 / prefer / favorite」 | 0.40 |
| MULTI_STEP_SUCCESS | 一轮内工具调用 ≥3 | 0.35 |
| CORRECTION | 「更正 / 纠正 / 不对 / 其实应该」 | 0.30 |
| TOOL_SUCCESS | 工具调用 ≥1 | 0.20 |
| TURN_COMPLETE | 对话完整完成 | 0.15 |
| USER_DISLIKE | 明确表达不满 | −1.0（一票否决） |

阈值分层：score ≥ 0.30 出情景提案；≥ 0.25 提取语义 fact（偏好 / 记住）；≥ 0.35 且工具调用 ≥3 提取程序步骤（去重保序）。`dislike` 正则不含「不要」「报错」（工作上下文高频词，属任务约束而非负反馈）。

### Memory 接口

```go
type Memory interface {
    LongTerm(ctx, sessionID) string
    AppendLongTerm(ctx, sessionID, delta) error
    Recall(ctx, query, RecallOpts) []RecallHit   // Kind/Score/Source/Title/Snippet
    Evaluate(ctx, sessionID, transcript) FormationResult
    WriteEpisode(ctx, EpisodeProposal) (string, error)
}
```

## 关键流程

### Capture（每次 run 结束自动跑）

```
chat.executeAgent → caps.CaptureAll（异步、独立超时）
  memory 能力：Evaluate(transcript) → 打分过滤
    score < 0（dislike 否决）→ 本轮不写情景/语义/程序（MEMORY.md 仍追加）
    score ≥ Episodic 阈值 → WriteEpisode（表 + FTS5 同事务 + 文件快照）
    score ≥ Semantic 阈值 → WriteFact；score ≥ Procedural → WriteProcedure
```

### Recall（向 LLM 注入记忆）

```
capability/memory.Preload（order=30）→ 两段 ContextPiece：
  memory  = MEMORY.md 尾部 4000 rune（长期记忆正文）
  recall  = RRF 融合三源命中：
    episodic   → memory_episodes_fts BM25
    semantic   → memory_facts_fts 三列 BM25，零命中/短查询回退子串扫描
    procedural → pkg.SplitTokens 切词逐 token 匹配 name/steps
  → 注入 system（workspace 之后、knowledge 之前）
```

### memory_write 工具路径

模型主动调用 `memory_write` → 直接写情景 / fact / procedure → FTS5 同事务索引，立即对后续召回可见。

## 约束

- 同 `(subject, key)` 的 fact 走 upsert（不新增行）；同 `name` 的 procedure 覆盖更新
- episode 文本中 `...</think>` 自动剥离，纯推理消息整行不入档
- FTS5 使用 `trigram` 分词器（unicode61 对中文退化）——重建或迁移时必须保留该选项
- 召回与形成均不阻塞首 token（Capture 异步、独立超时，失败仅告警）
