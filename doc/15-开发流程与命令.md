# 开发流程与命令

## 环境要求

Go 1.25.x、Node.js、Wails CLI v2；仅 Windows（amd64）。

## 常用命令

前端（在 `frontend/` 下）：

| 命令 | 用途 |
|---|---|
| `npm install` | 安装依赖 |
| `npm run dev` | 前端开发服务器（配合 wails dev） |
| `npm run build` | 类型检查 + 生产构建 |
| `npm run typecheck` | 仅类型检查（`vue-tsc --noEmit`） |
| `npm test` | 单元测试（`vitest run`） |
| `npm run test:watch` | 测试监视模式 |

后端（项目根）：

| 命令 | 用途 |
|---|---|
| `go build ./...` | 全量编译 |
| `go test ./internal/...` | 后端全量测试 |
| `go vet ./internal/...` | 静态检查 |

分层验证（**改小功能时用这一层，不必跑全量**）：

| 命令 | 用途 |
|---|---|
| `scripts/test.ps1 -Pkg <包> -Run <用例> -NoFront` | 最小闭环：只跑一个包里的一个用例（最快定位） |
| `scripts/test.ps1 -Pkg harness` | 只跑指定后端包（支持 `-Pkg service,harness`） |
| `scripts/test.ps1` | 核心后端包（service / harness / llm / tool）+ 前端类型检查与单测 |
| `scripts/test.ps1 -Full` | 全量后端 + 依赖方向门禁 + i18n 契约 + 前端（**提交前用**） |
| `scripts/test.ps1 -Full -Short` | 同上，跳过时序敏感用例（CI 用） |

示例：改了收件箱合入逻辑 → `powershell -File scripts/test.ps1 -Pkg service -Run TestInboxReviewFlow -NoFront`。

桌面壳（项目根）：

| 命令 | 用途 |
|---|---|
| `wails dev` | 开发模式（前端热更新 + 应用窗口） |
| `wails build` | 生产构建（含前端打包与运行时复制） |

门禁：

| 命令 | 用途 |
|---|---|
| `powershell -File scripts/check-boundaries.ps1` | 分层依赖方向 + 契约版本一致性校验 |
| `node scripts/i18n-sync.mjs check` | 中英字典键集合/顺序/值一致性 |

## 分层与依赖方向

`main` → `api` → `service` → `repo` → `domain`；`server`（HTTP+SSE）只依赖 `api/domain/event/pkg`；`harness`（内核）不依赖 gin/Wails；`pkg` 为叶子工具包，不依赖任何业务包。完整规则与校验项见 `doc/01-总体架构.md`。

## 测试策略

**只做长链路 / 复杂场景的自动化验证**：值得写测试的是「多组件协作、有状态迁移、失败路径、安全边界」这类读一遍代码推不出结论的流程；纯数据表、单字段 getter、单分支判断不单独写测试。

## 代码与注释规范

- **文件级**：每个文件顶部一段概要（1–3 行），说明职责与边界。
- **结构体字段**：必须有注释，写清单位与口径（如「毫秒时间戳」「千分比」「空 = 不限制」）。
- **函数/方法**：导出方法保留一行签名说明（动词开头，说清做什么）。
- **不写**：过程性长注释、改动历史、调试心路、外部项目对照。设计取舍只在「读代码推不出结论」时用一行补充，不展开论证。
- **事件载荷字段**：一律 `snake_case`。
- **错误码**：按域分段（持久化 / LLM / 工具 / 会话 / 记忆 / 技能 / 运行时等），新增错误复用所属段位。
- 分层依赖由门禁脚本强制，不新增反向依赖。

提交信息说清场景与根由（做了什么、为什么），不写「update / fix bug」这类无信息量描述；一次提交聚焦一件事。
