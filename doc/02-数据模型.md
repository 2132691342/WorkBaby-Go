# 02 数据模型

## 定位

`internal/domain/` 聚合根文件：一个领域一个文件，含 DO（持久化实体）+ DTO / REQ / VO / RESP（按需）+ 错误码常量。前端契约字段在 `RESP` / VO 上定；DB schema 与 DO 字段一一对应。

## 设计要点

- **JSON 字段 snake_case**（CLAUDE.md §2.5）：`json:"user_message_id"`，跨进程契约
- **时间戳统一毫秒整数**：`CreatedAt int64 \`gorm:"autoCreateTime:milli"\``
- **ULID + 领域前缀**：`NewID("SESSION")` → `SESSION_01ARZ3NDEK...`；trace 用 UUID v4；本机用户 id 固定 `"local"`
- **错误码段位**：1000–1999 通用/文件 · 2000–2999 配置/持久化 · 3000–3999 LLM/Provider · 4000–4999 工具/审批 · 5000–5999 Agent/Harness · 6000–6999 Memory · 7000–7999 RAG · 8000–8999 Skill/MCP · 9000–9999 Workflow/Pet/Channel/Cron
- **不暴露 Entity / VO 跨层**：service / repo / api / server 全部引用 domain 的 DO/DTO/REQ/VO/RESP
- **repo 是 domain 的薄持久化层**：只用 GORM + 必要 JSON 列；不感知事件总线 / 上层

### MessageDO 关键字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ID` | string | ULID with prefix `MESSAGE_` |
| `SessionID` / `Seq` | string / int64 | 复合索引 `idx_msg_session_seq` |
| `Role` | string | `user` / `assistant` / `tool` |
| `Content` / `Thinking` | string | 正文 / 推理 |
| `ToolCalls` | string | assistant 调用的 JSON 列表 |
| `ToolCallID` | string | tool 消息的对应 id |
| `Status` | string | `streaming` / `completed` / `failed` |
| `StopReason` | string | `end_turn` / `length` / `tool_calls` / `cancelled` / ... |
| `InputTokens` / `OutputTokens` / `CacheRead` / `TotalTokens` | int | 最终落库时填 |

### 检查点 step record（`agent_checkpoints.steps` JSON 列）

| 字段 | 说明 |
|---|---|
| `key` | `tool:<name>\|<args_json>`（幂等键） |
| `result` | 上次成功执行的结果（resume 时命中直接复用，不重放副作用） |

### 系统设置主键

| key 前缀 | 含义 |
|---|---|
| `chat.defaultTemperature` / `chat.defaultThinking` | 全局默认采样参数 |
| `tool.enabled.<name>` | 工具启停 |
| `agent.session_mode` | 全局默认权限模式（被会话级覆盖） |
| `chat.compressionRatio` | 压缩阈值比例 |

## 关键流程

### 一次 run 的落库顺序

1. `prepareRun` 分配 user + assistant 占位 → 写 `chat_messages`
2. 每轮 LLM 调完后 → 累加 `token_usages`（per-turn）
3. 工具调用前 → 写 `message_blocks`（kind=`tool_call`）
4. 工具结果回填 → 写 `message_blocks`（kind=`tool_result`）+ 写 `chat_messages`（role=`tool`）
5. run 结束 → `UpdateStatus` 写 assistant 的 content / thinking / tool_calls / usage
6. 检查点 → 写 `agent_checkpoints`（每轮一次）

### 消息序列重建协议

`toLLMMessages(hists)`：剥除 `status=streaming` 占位 + 剥除孤儿 tool 消息（`tool_call_id` 在全列表 assistant.tool_calls 中无匹配），保证发给 LLM 的消息流满足「assistant(tool_calls) 与其后 tool 结果同进同出」。

## 约束

- DO 与 `chat_messages` 表列一一对应；表名固定 `TableName()` 返回
- repo 层不做跨表 JOIN（不感知领域关系）；跨实体查询放 service
- 跨层结构体 inline 参数仅限 `tool/*` 快速解析（CLAUDE.md §2.3.1）
- 任何新增字段只增不删、零值兜底（CLAUDE.md §2.11）
