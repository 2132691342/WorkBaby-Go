# 02 · 数据模型

WorkBaby 的全部持久化模型：SQLite 单库 + GORM AutoMigrate 业务表 + FTS5 全文索引虚拟表，实体定义集中在 `internal/domain/`（每个聚合根一个文件），迁移入口在 `internal/db/migrate.go`。

## 设计

- **存储**：SQLite 单文件；启动期 `db.Migrate` 对 30 张业务表执行 AutoMigrate，失败即 fail-fast（半残库比不可用更危险）；`db.CreateFTS5` 单独建 3 张 FTS5 虚拟表（AutoMigrate 不覆盖虚拟表）。
- **聚合根**：`domain` 包只允许 import `pkg`；每个文件含 DO（落库实体）/ DTO（repo→service 传输）/ REQ（入参）/ RESP（出参）/ 枚举 / 错误变量（`Err*`，按段位划分）。
- **复杂字段文本化**：JSON 结构（工具调用、DAG 图、脚本、参数模板）一律以 `type:text` 字符串列落库，解析在 service 层完成，repo 只做无业务语义的读写。
- **软删**：两类形态并存——`deleted_at` int64 毫秒（会话 / 通道 / 定时任务 / 媒体预设 / sprite）与 `gorm.DeletedAt`（记忆、技能、MCP、知识库、工作流）。

## 核心契约

### 通用约定

| 约定 | 内容 |
|---|---|
| 主键 | `size:64` 字符串；值 = `pkg.NewID(prefix)` = `前缀_ULID`（前缀大写，≤16 字符） |
| 时间 | 跨边界一律 `int64` 毫秒时间戳；`created_at`/`updated_at` 由 `autoCreateTime:milli` / `autoUpdateTime:milli` 填充 |
| JSON | 跨边界 struct 的 json tag 一律 snake_case；敏感与磁盘路径字段 `json:"-"` 不外露 |
| 表名 | 每个 DO 以 `TableName()` 固定，不依赖 GORM 推断 |
| 单用户 | `user_id` 恒为常量 `local`（`domain.LocalUserID`）；租户恒 `default` |
| 索引 | 不做外键约束，跨表关系靠索引列 + service 层维护（`idx_*` / `uk_*` 命名） |

### ID 前缀（`domain/id.go`）

PROVIDER / SESSION / MESSAGE / BLOCK / SYS / MEM_EPISODE / MEM_FACT / MEM_PROC / SKILL / MCP / DOC / CHUNK / WORKFLOW / WF_EXEC / WF_NODE / CHANNEL / CH_LOG / CRON / MEDIA / MEDIA_PRESET / SPRITE / FOLDER / FILE；运行期另铸造 `RUN_`（执行 run）、`APR_`（审批）、`INP_`（补充输入）。

### approval_records（审批与补充输入）

暂停态持久化：run 因审批（ask）或补充输入（input_required）暂停时落 `pending` 行，进程重启后未决请求仍可见、可排空；决策后更新终态。

| 列 | 类型 | 说明 |
|---|---|---|
| id | string(64) PK | `APR_` / `INP_` 前缀 |
| run_id | string(64)，索引 idx_apr_run | 所属执行 |
| session_id | string(64)，索引 idx_apr_session | 所属会话 |
| kind | string(16)，索引 | `approval`（命令审批）/ `input`（补充输入） |
| command | text | 待审批命令，或补充输入的问题文本 |
| risk | string(32) | `needs_approval` / `irreversible` / `input_required` |
| status | string(16)，索引 idx_apr_status | `pending` / `approved` / `denied` / `timeout` / `cancelled` / `answered` |
| answer | text | input 类的用户回复 |
| expires_at | int64，索引 | 等待截止（默认 2 分钟） |
| created_at | int64 | 创建时刻 |
| decided_at | int64，默认 0 | 终态时刻 |

### agent_checkpoints（运行检查点）

跨进程重启可恢复的运行快照，前端可列「可恢复的运行」；`(run_id, turn)` 唯一索引 `uk_cp_run_turn`。repo 只做无业务语义的读写，DO↔harness 结构的转换在 service 层 adapter 完成。

| 列 | 说明 |
|---|---|
| id / session_id | 主键；会话索引 idx_cp_session |
| run_id / turn | 运行与轮次（联合唯一） |
| assistant_message_id | 本轮助手消息（恢复后消息归属的锚点），索引 |
| messages_json | `[]*llm.Message` 完整上下文 |
| state_json | harness.RunState（计数、停滞状态等） |
| usage_json | llm.TokenUsage 累计 |
| steps_json | 幂等恢复表：`map["tool:{name}:{args}"] → {content, duration_ms}`，记录已成功的工具调用；续跑命中直接复用结果，不重放副作用 |
| content / thinking | 断点处已累积的正文与推理文本 |
| created_at | 毫秒时间戳 |

### message_blocks（消息过程块）

assistant 消息的持久化分块：块即行，可索引、可按会话分页，前端据此重建工具时间线。

| 列 | 说明 |
|---|---|
| id / message_id+seq / session_id | 主键；消息内顺序复合索引 idx_block_message_seq；会话索引 |
| kind | `thinking`（推理文本）/ `tool_call`（模型决策+参数）/ `tool_result`（执行结果）/ `artifact`（结构化产出，如 todo 快照）/ `genui`（生成式 UI 片段） |
| payload | JSON 载荷文本 |

### token_usages（调用级用量）

与 `chat_messages` 的 token 列互补：消息只留最终助手消息的汇总值，本表按「每一次上游调用」落一行，多轮工具循环可被完整统计与回溯；`source` 区分 `chat / workflow / cron / media / memory` 五类场景，支撑仪表盘按场景拆分与对账（趋势聚合口径见 `TokenTrendREQ/RESP`，今日按小时分桶、其余按天）。

## 关键流程

- **启动迁移**：`Migrate` AutoMigrate 30 表 → `CreateFTS5` 建 3 张 FTS5（`IF NOT EXISTS` 幂等）。
- **写入**：service 层组装 DO（`pkg.NewID` 铸造主键）→ repo 写入；JSON 字段的序列化/反序列化在 service 完成。
- **会话删除级联**：删会话时 service 层同步删除其消息块（块不单独存活）。
- **软删过滤**：`deleted_at` 系表在查询侧过滤 `deleted_at = 0`；`gorm.DeletedAt` 系表由 GORM 自动过滤。
- **审批排空**：进程重启后把无等待方的 `pending` 行统一置 `cancelled`；用户续跑（resume）时审批重新发起。

## 约束

- `domain` 包禁止 import 任何上层（service / repo / api / 能力域 / wails），只可 import `pkg`。
- 磁盘绝对路径（media file_path、sprite file_path、files storage_path、file_changes path/snapshot_path、artifacts path）一律 `json:"-"`，前端只经 `/files/**` 受管通道访问内容。
- 错误码按段划分：1000 段文件/目录、2000 段持久化与迁移、3000 段 LLM、4000 段工具、5000 段会话/消息、6000 段记忆、7000 段知识库、8000 段技能与 MCP、9000+ 段媒体/定时/桌宠。
- FTS5 依赖 trigram 分词（中英混排可用）；虚拟表与实体表的双写由各自服务维护，不做触发器。
