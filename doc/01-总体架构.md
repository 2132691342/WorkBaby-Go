# 总体架构

## 分层模型

依赖只能自上而下，任何反向依赖都禁止（`scripts/check-boundaries.ps1` 强制校验）：

| 层 | 可以依赖 | 说明 |
|---|---|---|
| `main` | api / server / tray | 装配入口，无业务逻辑 |
| `internal/api` | service / harness / 各能力域 | Wails 绑定层，全项目唯一允许 import wails runtime 的地方 |
| `internal/server` | api / event | gin HTTP + SSE hub |
| `internal/service` | repo / harness / capability / llm | 业务编排 |
| `internal/capability` | harness / tool / 各能力域 | 上下文装配与 run 后沉淀的插件集 |
| `internal/harness` | llm / tool / memory / pkg | Agent 执行内核，不知道任何具体业务 |
| `internal/domain` | pkg | 聚合根单文件多形态 |
| `internal/repo` | domain / gorm | 持久化，不含业务 |
| `internal/pkg` | 标准库 / 第三方工具 | 叶子工具包，谁都可以用，它不用任何 internal 业务包 |

## 双主机通信

一次运行有两个服务在跑：

```
┌──────────────── WebView2 (Vue 3) ────────────────┐
│  业务请求 ──► http://127.0.0.1:{port}/api/v1/**  │
│  事件流   ──► GET /api/v1/events  (SSE)          │
│  系统能力 ──► Wails 绑定 (window.go.main.App.*)  │
└──────────────────────────────────────────────────┘
        │                                    │
   gin + SSE hub                      Wails runtime (Go)
        │                                    │
┌─────────────── internal/service ─────────────────┐
│  ChatService / TaskService / WorkflowService …   │
└──────────────────────────────────────────────────┘
```

- gin 只绑定 `127.0.0.1` 随机端口；端口通过 `app:ready` 事件与 `GetServerPort()` 绑定注入前端。
- 事件统一走 SSE：应用内 `event.Bus` 上的 `chat:*` / `pet:*` / `app:*` / `workflow:*` / `task:*` 被 hub 桥接出去，前端用统一解码器消费。
- Wails 绑定只保留系统能力：文件对话框、剪贴板、托盘、窗口形态切换、本地图片代读。业务一律不过绑定通道，避免前后端出现两条平行契约。

## 启动时序

`app.startup` 按固定顺序装配，任一步失败即中止（半残状态比不可用更危险）：

1. 解析数据目录（`runtime.Resolve`）→ 初始化日志
2. 内置运行时解压（Node / Python / PowerShell，失败仅告警）
3. 读取 `config.yaml` → 主密钥 → 打开 DB → 迁移 → 建 FTS5
4. 构造 repo / service / LLM Registry（解密 apiKey）
5. 注册工具与能力 → 信任根 → 后台任务队列 → 通知通道 → 工作流执行器 → 定时调度
6. 桌宠播种 → 排空遗留审批 → 标记中断消息 → 事件桥接
7. `main` 启动 gin → `EmitReady(serverPort)` → 前端建立 HTTP 连接

## 目录结构

```
main.go / app.go          Wails 生命周期与装配
internal/
  api/                    Wails 绑定（一个文件一个功能域）
  server/                 gin 路由 + SSE hub
  service/                业务编排（chat / task / workflow / memory / …）
  capability/             上下文能力插件（persona / workspace / memory / …）
  harness/                Agent 执行内核（runner / compress / checkpoint / delegate）
  llm/                    Provider 适配（anthropic / openai / ollama）
  tool/                   工具契约与内置工具
  workflow/               DAG 执行器与节点
  mcp/ skill/ memory/ rag/ cron/ channel/ pet/ tray/ runtime/ pkg/ …
frontend/
  src/src/                Vue 应用源码（components / stores / api / i18n）
  src/wailsjs/            Wails 生成的绑定与运行时
build/ scripts/ runtimes/ 构建产物、安装脚本、随包运行时
```

## 事件协议

所有「Agent 在干活」的入口共用同一套事件命名：

| 前缀 | 产生方 | 典型事件 |
|---|---|---|
| `chat:` | harness run | `chat:stream` / `chat:thinking` / `chat:tool` / `chat:tool-result` / `chat:stats` / `chat:done` / `chat:error` / `chat:approval` / `chat:compressed` |
| `task:` | 后台任务队列 | `task:created` / `task:started` / `task:done` |
| `workflow:` | 工作流执行器 | 节点级进度与终态 |
| `pet:` | 桌宠控制 | `pet:show` / `pet:hide` / `pet:state` |
| `app:` | 应用生命周期 | `app:ready` / `app:open-file` |

事件带单调递增 `seq`，SSE 断线时浏览器回传 `Last-Event-ID`，服务端从 `RunEventLog` 重放；缓冲被覆盖则下发 `chat:gap`，前端转全量快照兜底。
