# 构建与分发

仅面向 Windows（amd64）。产物为单个可执行文件 + 内置运行时归档，安装包由 NSIS 生成。

## 前置条件

- Go 1.25.x
- Node.js（前端构建）
- Wails CLI v2（`wails` 命令）

## 构建配置（`wails.json`）

| 项 | 值 | 说明 |
|---|---|---|
| name / outputfilename | WorkBaby | 产物名 `WorkBaby.exe` |
| frontend:install / build | `npm install` / `npm run build` | 构建前自动装依赖并打包前端 |
| frontend:dev:watcher | `npm run dev` | 开发模式前端热更新 |
| wailsjsdir | ./frontend/src | Wails 绑定生成位置 |
| productVersion | 0.1.0 | 应用版本（`/meta/version` 来源之一） |
| fileAssociations | md / txt / pdf | 安装器注册的文件关联 |
| postBuildHooks | `scripts/copy-runtimes.ps1 ${bin}` | 构建后复制内置运行时 |

## 内置运行时

`runtimes/` 目录为源：`manifest.json` + 每个资产一个归档。

| 资产 | 归档 |
|---|---|
| Node.js | node v24.18.0 win-x64（zip） |
| Python | python 3.12.13 win-x64（tar.gz） |
| PowerShell | powershell 7.5.2 win-x64（zip） |

- 构建后置钩子把 `runtimes/` 复制到 `<binDir>/runtimes` 与 `<buildDir>/windows/runtimes`（后者供 NSIS 打包）；manifest 中声明的归档缺失时**构建直接失败**，不会产出缺运行时的安装包。
- 运行时在应用首启解压到 `{home}/runtimes/{资产}/{版本}`，其 bin 目录前置到子进程 PATH（脚本执行、MCP server 均受益），无需用户预装。

## 构建产物

| 产物 | 位置 |
|---|---|
| 可执行文件 | `build/bin/WorkBaby.exe` |
| 运行时副本 | `build/bin/runtimes/` |
| 安装程序脚本 | `build/windows/installer/project.nsi` |
| NSIS 安装器 | `build/bin/WorkBaby-amd64-installer.exe` |

前端产物在构建阶段由 `npm run build` 生成并**嵌入二进制**，运行时通过 Wails AssetServer 提供；`/files/**` 路径映射到受管文件服务，其余路径回落到嵌入的前端资源。

## 数据目录与卸载

- 数据根 `{home}`：默认 `%APPDATA%\WorkBaby`，可用环境变量 `WORKBABY_HOME` 覆盖（便于多实例/便携部署）。
- 应用数据（库、日志、配置、记忆、快照、技能、运行时、受管文件）全部在 `{home}` 下，卸载程序不主动删除；工作区沙箱在用户绑定的工作目录内（`.workbaby/`）。

## 门禁脚本

| 脚本 | 用途 |
|---|---|
| `scripts/check-boundaries.ps1` | 用 `go list` 校验分层依赖方向与契约版本一致性 |
| `scripts/copy-runtimes.ps1` | 构建后复制内置运行时并校验归档完整性 |

## 常见失败点

- `runtimes/manifest.json` 与实际归档不一致 → 构建 fail fast。
- 前端 `npm install` / `npm run build` 失败 → 整个构建中断（先单独跑通前端构建更易定位）。
- 依赖方向或契约版本不一致 → `check-boundaries.ps1` 报错，需先修复再打包。
