# 开发流程与命令

## 日常命令

| 场景 | 命令 |
|---|---|
| 开发 | `wails dev`（前端热更新 + Go 热重启） |
| 仅前端调样式 | `cd frontend; npm run dev`（浏览器打开，调不到 Go 绑定） |
| 构建 | `wails build` |
| 后端测试 | `go test ./...`；改单个能力时按域跑（见测试地图的 `-run` 示例），不必全量 |
| 后端边界校验 | `powershell -File scripts/check-boundaries.ps1` |
| 前端类型检查 | `cd frontend; npm run typecheck` |
| 前端测试 | `cd frontend; npm run test` |
| 运行时复制 | 构建后自动执行 `scripts/copy-runtimes.ps1` |

### 按域跑测试

场景实现是私有函数（`testXxx`），只由聚合父测试以 `t.Run` 调用，因此 `-run` 可以精确到「一类行为」甚至「单个场景」：

```bash
# 只跑闸门与审批的 7 个场景（改审批逻辑时）
go test ./internal/harness/ -run TestRunnerApprovalGate

# 只跑 ReAct 主循环里的截断重发这一个场景
go test ./internal/harness/ -run 'TestRunnerReActLoop/truncated_retry'

# 只跑消息清洗的协议约束（改 toLLMMessages 时）
go test ./internal/service/ -run TestChatLLMMessageHygiene

# 看某个父测试下有哪些场景
go test ./internal/harness/ -run TestRunnerReActLoop -v
```

## 工程约定

- **先读再写**：改前通读目标文件与对应测试；沿用既有模式，不引入第二套做法。
- **最小改动**：外科手术式修改，不顺手格式化无关代码；只清理自己改动产生的冗余。
- **修 Bug 先复现**：能写成测试的先写测试；改完跑受影响包的测试，再跑全量。
- **验证命令**：后端 `go build ./... && go test ./...`，前端 `npm run typecheck && npm run test`。
- **提交信息**：写清场景与根因，不写「fix bug」。
