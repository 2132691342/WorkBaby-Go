# 10 工作流引擎

## 定位

`internal/workflow/` 实现 DAG 工作流：用户编排节点图 → 触发执行 → 节点按拓扑分层串行、层内并行运行。可被 agent（`run_workflow` 工具）或 cron 触发；前端可视化编辑（Vue Flow 双向转换）。

## 设计要点

- **图 = 节点 + 变量引用**：`NodeDef{ID, Type, Deps, Config, Inputs, Branch, Pos}`；DAG 校验（ID 合法性、deps 存在、Inputs 引用、环检测、必填 schema、branch 归属）在 graph 层
- **执行**：Kahn 拓扑分层 → 逐层执行 → 层内并发 → condition 分支跳过传播
- **节点类型**（7 种）：`llm`（配 tools 走 ReAct 子循环，否则单次补全）/ `tool` / `condition` / `http` / `code` / `human_input` / `channel`
- **并发安全**：runLayer 层内兄弟 goroutine 对 outputs / conditionOutputs / skipped 的读写均持锁
- **HumanInput**：执行前向节点 inputs 注入 `__executionId__` / `__nodeId__`，节点据此拼 waiter key；`workflow:input-required` 事件 + resolver 阻塞等待前端回填（ttl 可配，默认 24h）
- **暂停 / 取消**：暂停在层边界生效（waitIfPaused）；取消只发信号，终态由 Run 流程单一写入者收束

## 核心契约

### 图定义（Graph JSON，workflows 表持久化）

```go
type Graph struct {
    Name    string
    Inputs  map[string]string // 图级入参：key → 类型
    Nodes   []*NodeDef
    Outputs map[string]string // 图级输出：key → "nodeId.field"
}
type NodeDef struct {
    ID     string
    Type   NodeType          // llm/tool/condition/http/code/human_input/channel
    Deps   []string          // 上游节点 ID
    Config map[string]any    // 节点参数（schema 校验）
    Inputs map[string]string // 入参变量引用：key → "nodeId.field"
    Branch string            // condition 分支归属（true/false/自定义）
    Pos    *Pos              // 画布坐标
}
```

`SaveGraph` / `GraphToDAG` 与前端 Vue Flow 格式双向转换，节点 Inputs / 图级 Inputs / Branch / Pos 全量保留。条件分支：condition 节点输出 `branch` 字段，下游 `NodeActive` 据其 Deps 中第一个命中的 condition 分支决定运行或跳过（跳过向下游传播）。

### 执行记录

| 表 | 状态 |
|---|---|
| `workflow_executions` | `running` / `paused` / `completed` / `failed` / `cancelled` |
| `workflow_node_executions` | 每节点 inputs/outputs/status/起止时间 |

前端状态契约统一小写。事件经 SSE 桥接 `workflow:*` 前缀（scope=workflow，按 executionID 过滤）：started / node-start / node-done / completed / failed / cancelled / paused / resumed / input-required。

## 关键流程

### 分层执行

```
layers = TopologicalLayers(graph)   // Kahn
for each layer:
  waitIfPaused（层边界检查暂停信号）
  for node in layer（并发）:
    持锁读 upstream = ResolveUpstream + RenderConfigMap（{{#nodeId.field#}} 模板渲染）
    注入 __executionId__ / __nodeId__
    impl.Execute(ctx, inputs, renderedCfg, upstream)
    持锁写 outputs[node.ID]（condition 节点另写 branch 缓存）
  任一节点失败 → 本层收束 → state=failed
```

### LLM 节点

- 配了 tools 且装配方提供 ReactFunc → `WorkflowReactor.React` 复用 harness 的 ReAct 主循环（RunOnce：多轮工具、预算与停滞熔断），工具白名单 = 节点声明的 tools（defs 层与执行侧双收紧）
- 未配 tools → 单次补全（prov.Stream）
- 两路均逐轮落 `token_usages`（Source=workflow）；未配置 ToolGate 时直接放行（nil 门 = 放行语义）

### HumanInput 回填

```
节点阻塞在 resolver.Resolve(executionID, nodeID, prompt, ttl)
  → 发布 workflow:input-required（executionID/nodeID/prompt）
前端提交 POST /executions/{id}/input {node_id, value}
  → resolver.Deliver 按 executionID|nodeID 精确投递 → 节点返回 {value}
```

## 约束

- 图必须无环、ID 唯一、deps / Inputs 引用必须存在（Validate 失败拒绝保存与运行）
- 节点超时独立于整体（HTTP 30s、Code 10s/60s 内建）；LLM 节点无独立超时，随 run ctx
- human_input 暂停整个 workflow 等人工回复，超时按失败收束（可 Cancel 打断）
- 进程重启后内存中的暂停态丢失，DB 残留 paused 行无人接管（需手动 Cancel）
