# 开发流程与命令

## 环境要求

Go 1.25.x、Node.js、Wails CLI v2；仅 Windows（amd64）。

## 常用命令

前端（在 `frontend/` 下）：

| 命令 | 用途 |
|---|---|
| `npm install` | 安装依赖 |
| `npm run dev` | 前端开发服务器（配合 wails dev） |
| `npm run build` | 类型检查 + 生产构建 |
| `npm run typecheck` | 仅类型检查（`vue-tsc --noEmit`） |
| `npm test` | 单元测试（`vitest run`） |
| `npm run test:watch` | 测试监视模式 |

后端（项目根）：

| 命令 | 用途 |
|---|---|
| `go build ./...` | 全量编译 |
| `go test ./internal/...` | 后端全量测试 |
| `go vet ./internal/...` | 静态检查 |

分层验证（改小功能时不必跑全量）：

| 命令 | 用途 |
|---|---|
| `powershell -File scripts/test.ps1` | 核心后端包（service / harness / llm / tool）+ 前端类型检查与单测 |
| `powershell -File scripts/test.ps1 -Pkg harness` | 只跑指定后端包（支持 `-Pkg service,harness`） |
| `powershell -File scripts/test.ps1 -Full` | 全量后端 + 依赖方向门禁 + 前端（提交前用） |

桌面壳（项目根）：

| 命令 | 用途 |
|---|---|
| `wails dev` | 开发模式（前端热更新 + 应用窗口） |
| `wails build` | 生产构建（含前端打包与运行时复制） |

门禁：

| 命令 | 用途 |
|---|---|
| `powershell -File scripts/check-boundaries.ps1` | 分层依赖方向 + 契约版本一致性校验 |

## 分层与依赖方向

`main` → `api` → `service` → `repo` → `domain`；`server`（HTTP+SSE）只依赖 `api/domain/event/pkg`；`harness`（内核）不依赖 gin/Wails；`pkg` 为叶子工具包，不依赖任何业务包。完整规则与校验项见 `doc/01-总体架构.md`。

## 测试策略

只保留**长链路 / 复杂场景**测试，简单纯函数测试不单独维护（改小功能时验证成本更低、定位更快）。

后端（`internal/**/*_test.go`）：

| 领域 | 覆盖 |
|---|---|
| 服务端到端 | `service/integration_test.go`、`service/chat_test.go`、`service/checkpoint_test.go`、`service/skill_sync_test.go` |
| 权限与安全 | `service/security_test.go`、`tool/file/guard_test.go`、`tool/planmode/planmode_test.go`、`runtime/runtimes_test.go` |
| Agent 内核 | `harness/runner_test.go`、`harness/compress_test.go`、`harness/guardrails_test.go`、`harness/resilience_test.go` |
| 数据链路 | `memory/memory_test.go`、`rag/rag_test.go`、`workflow/executor_test.go` |
| 协议与传输 | `mcp/client_test.go`、`server/server_test.go`、`llm/conformance_test.go` |
| 工作区一致性 | `tool/workspace_link_test.go` |

前端（`frontend/src/src/**/__tests__`）：

| 文件 | 覆盖 |
|---|---|
| `chat/__tests__/streamPipeline.spec.ts` | SSE → 解码 → 批渲染 → 历史块还原 全链路 |
| `chat/__tests__/merge.spec.ts` | 乐观消息与权威快照合并、流式收尾三态决策 |

测试文件中不保留无 Test 函数以外的私有夹具以外的冗余；共享 mock 夹具放在 `harness/runner_helpers_test.go`。

## 代码与注释规范

- **文件级**：每个文件顶部一段包/文件概要（1–3 行），说明职责与边界。
- **结构体字段**：必须有注释，尤其是单位、口径、枚举含义（如「毫秒时间戳」「千分比」「空 = 不限制」）。
- **函数/方法**：导出方法保留一行签名说明（动词开头，说清做什么）；不写过程性长注释、不写改动历史、不引用外部项目。
- **事件载荷字段**：一律 `snake_case`。
- **错误码**：按域分段（持久化 / LLM / 工具 / 会话 / 记忆 / 技能 / 运行时等），新增错误复用所属段位。
- 分层依赖由门禁脚本强制，不新增反向依赖。

## 提交约定

提交信息说清场景与根由（做了什么、为什么），不写「update / fix bug」这类无信息量描述；一次提交聚焦一件事。
