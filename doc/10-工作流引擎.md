# 工作流引擎

可视化 DAG：把「模型调用 / 工具 / 代码 / 条件 / HTTP / 人工输入 / 通知」编排成可复用、可审计、可中断的流程。

## 模型

| 表 | 说明 |
|---|---|
| workflows | 名称、描述、graph（DAG JSON：节点 + 边）、启用状态 |
| workflow_executions | 一次运行：输入/输出、状态（pending / running / paused / completed / failed / cancelled）、错误、起止时间 |
| workflow_node_executions | 单节点运行：节点类型与 id、状态（pending / running / completed / failed / skipped / waiting_input）、输入/输出、起止时间 |

节点类型（7 类）：

| 类型 | 职责 |
|---|---|
| llm | 调用模型完成任务；可启用 ReAct 分支（带工具的多轮），未配置工具时回落单次补全 |
| tool | 调用内置工具（受工作区沙箱与权限模式约束） |
| code | 执行脚本（语言与解释器固定映射） |
| condition | 按表达式（expr）求值决定分支走向 |
| http | 发起 HTTP 请求并把响应传给下游 |
| human_input | 暂停等待人工输入，收到输入后继续 |
| channel | 通过通知通道发送消息 |

## 执行器

- 图先经校验（节点 id 唯一、边指向存在、可推导入口，无环要求由 DAG 定义保证）后才允许运行。
- 调度按**层**推进：同层节点并发执行，层内全部完成后进入下一层；节点输出写入执行上下文供下游引用。
- 状态流转集中在执行器：每节点的开始/结束写 `workflow_node_executions`，整轮终态写 `workflow_executions`。
- 中断语义：cancel 打断执行中节点并落 cancelled；pause / resume 支持长流程挂起恢复；human_input 节点使执行进入 waiting_input。
- 审计：执行与节点记录都可列表查询，供前端回放与排查。

## 事件

执行过程经事件总线实时下发（前端 `scope=workflow` 订阅 SSE）：`workflow:started`、`workflow:node-start`、`workflow:node-done`、`workflow:paused`、`workflow:resumed`、`workflow:input-required`、`workflow:completed`、`workflow:failed`、`workflow:cancelled`。

## 与其他模块的关系

- 可由 Agent 经 `run_workflow` 工具触发，也可由定时任务（cron 的 `run_workflow` 动作）触发。
- LLM 节点与聊天共用同一个 Agent 执行内核（同样的工具链、护栏与压缩策略）。
- 结束可经 channel 节点发通知（邮件 / Webhook / 控制台）。

## 不变量

- 未通过校验的图不可运行；节点 id 唯一、边必须指向存在的节点。
- 同层并发、跨层顺序推进；节点记录与执行记录都以数据库为真相源。
- 取消、暂停、恢复都是显式状态，不靠进程内标记推断。
