# WorkBaby 总体架构

## 分层架构

依赖只能自上而下，反向依赖由 `scripts/check-boundaries.ps1` 门禁校验。

```
┌────────────── Wails 壳 (package main) ──────────────┐
│ main.go / app.go：单实例 → wails.Run → 生命周期钩子      │
│ AssetServer：/files/** → FileServer；其余 → 嵌入前端资源  │
└───────┬───────────────────────────────┬─────────────┘
        │ OnStartup: Handler.Startup      │ Bind: App（系统能力）
        ▼                                 ▼
┌──────── HTTP (gin) + SSE ──────────────┐   ┌── Wails runtime ──┐
│ internal/server：router / sse / mw      │   │ 对话框/剪贴板/托盘  │
└───────┬─────────────────────────────────┘   └───────────────────┘
        ▼
┌──────── internal/api (Handler) ─────────┐   ← 唯一 import wails runtime
│ 聚合全部 service；方法即路由/绑定入口        │
└───────┬─────────────────────────────────┘
        ▼
┌──────── internal/service（编排） ────────┐
│ ChatService / TaskService / WorkflowSvc … │
└──┬─────────────┬─────────────┬──────────┘
   ▼             ▼             ▼
capability     harness       llm / tool / workflow / memory / rag /
（上下文插件）  （Agent 内核）  mcp / skill / cron / channel / pet / keepawake …
   │             │
   ▼             ▼
┌──────── internal/repo（持久化） ─────────┐
└───────┬─────────────────────────────────┘
        ▼
┌──── internal/domain（模型） ────┐  + internal/db（SQLite / FTS5）
└─────────────────────────────────┘  + internal/event（事件总线 + 日志）

前端：Vue 3 / TS / Vite（frontend），经 HTTP+SSE 消费业务，经 Wails 绑定取系统能力
```

| 层 | 可以依赖 | 说明 |
|---|---|---|
| `main` | api / server / tray / singleinstance | 装配入口，无业务逻辑 |
| `internal/api` | service / harness / 各能力域 | Wails 绑定层；唯一允许 import wails runtime 的地方 |
| `internal/server` | api / domain / event / pkg / gin | gin HTTP + SSE hub |
| `internal/service` | repo / harness / capability / llm / 能力域 | 业务编排（不 import gin / wails） |
| `internal/capability` | harness / tool / 能力域 | 上下文装配与 run 后沉淀插件集 |
| `internal/harness` | llm / tool / memory / pkg | Agent 执行内核（不 import gin / wails） |
| `internal/llm` | pkg | Provider 抽象与适配 |
| `internal/tool` | pkg / 各工具子包 | 工具契约、注册中心、策略门 |
| `internal/domain` | pkg | 聚合根单文件多形态 |
| `internal/repo` | domain / db / gorm / pkg | 持久化，不含业务 |
| `internal/pkg` | 标准库 / 第三方 | 叶子工具包；不 import 任何 internal 业务包 |

## 启动装配顺序

`main()` → `app.startup(ctx)` → `Handler.Startup(ctx)`。任一步失败即返回错误终止启动。关键顺序：

| # | 步骤 | 产物 / 说明 |
|---|---|---|
| 1 | `runtime.Resolve()` | `{home, db, log, cfg}` |
| 2 | `pkg.Init(paths.Log)` | 全局日志器 |
| 3 | 内置运行时 `Ensure()` | 同步解压（失败仅告警；MCP 子进程 PATH 依赖它） |
| 4 | `config.Init` + `EnsureUserConfig` | 强类型配置 + 主密钥落盘 |
| 5 | `pkg.NewCipherFromB64(masterKeyB64)` | 加解密器（apiKey 用） |
| 6 | `db.Open` → `db.Migrate` → `db.CreateFTS5` | SQLite 打开、业务表迁移、FTS5 虚拟表 |
| 7 | 构造 repo（sess / msg / prov / set / usage） | 持久化句柄 |
| 8 | `model.json` 存在则同步入库 | 失败仅告警 |
| 9 | LLM Provider 注册中心（解密 apiKey） | 未就绪项打日志 |
| 10 | 工作区 + 工具前置设施 | `wsResolver`、变更/工件服务、工具注册表、审批服务 |
| 11 | 注册内置工具 | exec / skillrun / 文件读写编辑检索 / web / http / 搜索 / 纯函数 / 文档 / 归档 / 委派 / 计划模式 |
| 12 | 知识库 RAG（FTS5 检索 + 索引） | `knowledgeSvc` |
| 13 | 记忆系统 | `memSvc`（记忆落点晚绑定 chatSvc） |
| 14 | 技能系统 | 内置技能入库 + 全局目录同步（工作区目录在 run 期叠加） |
| 15 | MCP | `mcp.json` 同步 + 子进程对齐（失败标记 unready） |
| 16 | 构造 `ChatService` + 能力链 | DataHome / CheckpointStore / EventLog / MessageBlocks / RunRecords / ExecutionRegistry / ApprovalService / SkillSync |
| 17 | 目录信任 + 计划模式 | 恒信任根：workspace / workspaces / runtimes / knowledge / files |
| 18 | 后台任务 worker | `taskSvc.Start()` |
| 19 | 通知通道 | email / webhook / console |
| 20 | 工作流引擎（DAG） | 节点注册 + `workflowSvc` |
| 21 | 能力注册表 | persona(10) / environment(15) / workspace(20) / todo(25) / session_var(28) / memory(30) / knowledge(40) / skill(50) / workflow(60) / inbox(70) → `chatSvc.WithCapabilities`；inbox 只走 Capture 通道（终局抽取候选入收件箱），无 Preload/工具 |
| 22 | 定时调度 | cron + `run_workflow` 动作；执行全程经 keepawake 持有防休眠引用 |
| 23 | 文件 / 工作区服务 | `folderSvc` / `fileSvc` / `workspaceSvc` |
| 24 | 桌宠 + 启动排空 | 内置形象播种、遗留审批作废、中断 run 标记 |

第 10、13 步的闭包在装配期引用 `chatSvc`（此时为 nil），实际调用发生在 run 期，属**晚绑定**：文件沙箱、快照目录、记忆落点、exec cwd 全部跟随会话工作区。

随后 `main` 继续：起 gin + SSE hub → 监听 `127.0.0.1:0`（随机端口）→ 发 `app:ready`（携带 `server_port`）→ 起系统托盘 → 补发暂存的文件打开请求。

## 一次聊天请求的完整链路

```
前端 chat store
  │ POST /api/v1/chat/stream {session_id, content, temperature, thinking_effort}
  ▼
internal/server/router.go → h.SendStream(req)
  ▼
ChatService.SendStream
  1. 取会话，缺 provider/model 时回退首个 enabled Provider
  2. 分配 user / assistant 两条消息 seq；登记执行平面；INSERT user 消息 + assistant 占位(streaming)
  3. runs.set(sessionID, runID, cancel)
  4. go runLLM(...) 异步开跑，HTTP 立即返回 {run_id, session_id, msg ids}
  ▼
ChatService.executeAgent
  · 同步会话工作区技能目录（失败仅告警）
  · 拉历史 → toLLMMessages（剥孤儿 tool / 空 assistant 占位）
  · buildSystem：能力 PreloadAll 按序装配 + 压缩保留指示 + 沙箱约束
  · 构造 Runner 链（压缩 / 参数合并 / 工具 / 检查点 / 工具门 / 目录信任 / 插话 / 轮次调整）
  ▼
harness.Runner（多轮 ReAct）
  每轮：压缩 → 请求 LLM（建流有界重试）→ 增量发出 → 工具执行回填 → 检查点
  ▼
sink → 映射为 chat:* 事件
  chat:stream.start / chat:stream / chat:thinking / chat:turn-start / chat:tool /
  chat:tool-start / chat:tool-result / chat:checkpoint / chat:stats / chat:skill /
  chat:todo / chat:compressed / chat:retry / chat:error / chat:done
  同时工具调用/结果/产物落 message_blocks
  ▼
ChatService.emit → eventLog.Append（分配 seq）→ bus.Publish
  ▼
SSEHub（按 scope + runID 过滤）→ GET /api/v1/events?scope=chat&runId=…
  ▼
前端 stream.ts + ChatStreamDecoder → chat store 渲染
  ▼
run 收尾：assistant 消息落库(status/stop_reason/tokens/cost) → 发 chat:done →
  用量落 token_usages → 执行平面终态 → run 后沉淀（记忆形成等，异步独立超时）
```

恢复路径：崩溃 / 中断后同一 `runID` 经 `POST /chat/stream/:id/resume` 续跑，前端重挂 SSE；已完成工具调用经检查点复用，不重放副作用。

## 事件总线与 SSE 重放

**seq 分配**（`internal/event/runlog.go`）

- 每个 run 独立、进程内单调递增 `seq`，注入事件载荷。
- 每 run 环形缓冲（容量 128）；最多跟踪 16 个 run，超限按逻辑时钟淘汰。
- 单条事件超过 32KB 时只分配序号、内容置占位，重放遇到占位判定「不覆盖」。
- 可选 JSONL 文件 sink：`{home}/runs/{runID}.jsonl`，保留最近 50 个。
- 序号是进程内语义，不落库。

**SSE 重放**（`internal/server/sse.go`）

| 环节 | 行为 |
|---|---|
| 订阅桥接 | hub 订阅 `chat:` / `pet:` / `app:` / `workflow:` / `task:` 前缀事件 |
| 过滤 | 按客户端 `scope`（前缀匹配）与 `runID` 过滤 |
| 重放起点 | 优先 `Last-Event-ID` 头，其次 `last_event_id` query |
| 首连重放 | `afterSeq=0` 时补发该 run 已缓存全部事件，覆盖 POST 返回 → SSE 握手窗口 |
| gap 回补 | 缓冲已滚动覆盖或超大占位时先下发 `chat:gap`，前端转全量快照 |
| 就绪握手 | 重放后发送 `sse-ready` |
| 心跳 | 每 30s 发具名 `ping` 事件（非注释帧），供前端 watchdog 区分空闲与假死 |
| 慢客户端 | channel（容量 256）满时关闭连接，触发浏览器重连靠 `Last-Event-ID` 补齐 |
| 帧格式 | `seq>0` 时输出 `id: <seq>`，随后 `event:` 与 `data:` |

**前端可靠性**（`frontend/src/src/api/stream.ts`）：`Last-Event-ID` 重放、watchdog 假死检测、指数退避重连；重连成功后重拉会话快照补齐窗口。

## 并发与事务边界

| 边界 | 机制 |
|---|---|
| SQLite 单写者 | 连接池收敛单连接；DSN 带 WAL + busy_timeout + 外键 |
| run 级并发 | `ChatService` 会话级互斥锁（建流 / 插话 / 后台 run 的同会话串行，跨会话并行）；`runRegistry` 按 `sessionID → cancel`；同会话已有活动 run 时续跑返回 5002 |
| 消息 seq 分配 | `seqMu` 保护水位 map；user / assistant / tool / steer 统一分配，避免游标分页漏消息 |
| 能力 Preload | 按 order 升序串联；单能力失败仅告警跳过，不阻断 run |
| 能力 Capture | 脱离 run ctx 异步执行，每能力独立 30s 超时 |
| 工具并行 | 同轮全只读且允许并行时才并行（默认并发 4），结果按调用顺序回填；写工具严格串行 |
| 工具 panic | 单工具包 `recover`，转错误结果回填，不拖垮 run |
| 后台任务 | 有界 worker（2 worker / 队列 32），context 取消传播；不占前台会话 run 槽 |
| 事务边界 | 持久化收敛在 repo 层；批量计量走 `BatchCreate` |

## 依赖方向门禁

`scripts/check-boundaries.ps1` 用 `go list` 权威依赖图断言：

| 检查项 | 规则 |
|---|---|
| `pkg-no-internal` | `internal/pkg` 不得 import 任何 internal 业务包 |
| `domain-no-upward` | `internal/domain` 只允许 `internal/pkg` |
| `repo-no-upward` | `internal/repo` 不得 import api / service / server / harness / llm / tool / skill / mcp / memory / rag / workflow / pet / channel / cron / runtime / config / event |
| `service-no-http` | `internal/service` 不得 import gin / wails |
| `server-no-downward` | `internal/server` 只允许 api / domain / event / pkg / gin |
| `harness-no-http` | `internal/harness` 不得 import gin / wails |
| `contract-version-sync` | `internal/domain/contract.go` 的 `ContractVersion` 必须与 `frontend/src/src/api/contract.ts` 一致 |

配套约定：事件载荷字段一律 `snake_case`；业务 API 统一前缀 `/api/v1`，仅 GET / POST；Wails 通道只承载系统能力与 `app:*` 生命周期事件，业务一律走 HTTP + SSE。
