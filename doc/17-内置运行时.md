# 内置运行时

随应用分发的 Node.js / Python / PowerShell 运行时，让脚本执行、技能脚本与依赖这些解释器的 MCP server 开箱可用，不要求用户预装。

## 资产与清单

`runtimes/` 目录为源：`manifest.json` 声明资产（id、版本、归档文件名、目标子目录），每个资产一个归档。

| 资产 | 当前版本 | 归档格式 |
|---|---|---|
| Node.js | 24.18.0 win-x64 | zip |
| Python | 3.12.13 win-x64 | tar.gz |
| PowerShell | 7.5.2 win-x64 | zip |

## 打包与定位

- 构建后置钩子把 `runtimes/` 复制到可执行文件同级的 `runtimes/` 与安装器输入目录；清单声明的归档缺失时构建直接失败，避免产出缺运行时的安装包。
- 运行期定位内置资源目录（含 `manifest.json` 的目录）的优先级：显式指定 → 生产可执行文件同级 `runtimes/` → 开发态工作目录 `runtimes/`。

## 首启解包与 PATH 注入

- 启动时按清单把归档解压到 `{home}/runtimes/{资产}/{版本}`；重复启动幂等（已存在即跳过），失败仅告警，不阻断应用启动。
- 解包完成后，各运行时 bin 目录经 `BinDirs()` 前置到子进程 PATH：
  - 技能脚本执行（`run_skill_script`）用其中的 node / python；
  - `exec` 工具在受限环境下也能找到解释器；
  - MCP server 的 `npx` / `uvx` 类命令依赖前置 PATH 才能启动。
- 应用内不修改系统 PATH，只在派生子进程时注入，退出即失效。

## 解压安全

- 每个归档条目做**路径穿越校验**：规范化后必须落在目标目录内，拒绝 `../` 逃逸。
- 限额保护：限制解压条目数与总字节数，超过即中止（防归档炸弹）。
- 单条资产解压失败只影响该资产，其余资产与启动流程继续。

## 状态查询

`GET /api/v1/meta/runtime` 返回各资产的状态：是否就绪、内置资源目录、解包目标路径与错误信息，便于前端与排查定位「解释器缺失」类问题。

## 不变量

- 清单是唯一真相源：声明的归档必须存在（构建期强校验），解包路径由 id + 版本确定。
- 解包幂等，重复启动不重复写入；不做系统级环境修改。
- 运行时缺失只降级相关能力（脚本 / MCP），不阻断应用启动。
