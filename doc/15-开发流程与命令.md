# 15 开发流程与命令

## 定位

单人 / 小团队本地开发流程：分支模型（GitHub Flow 简化）、环境要求、常用命令、验收清单、提交规范。

## 设计要点

- **GitHub Flow 单主干**：`main` 唯一长期分支；功能在本地分支开发，CI（暂未启用）通过后合并
- **无强制 release tag**：内部版本（v0.0.x）直接打 commit 标记
- **Wails 单实例**：开发期 `wails dev` 启动后，重复启动会被命名互斥拦下并转 IPC

## 环境要求

| 工具 | 版本 |
|---|---|
| Go | 1.25.x |
| Node | 20.x 或更新 |
| Wails CLI | v2.12.x |
| GCC（仅 Linux/macOS） | 11.x+（Windows 上 wails 用 msvc，不需要） |

前端：`npm install` 装依赖。

## 常用命令

### 开发

```bash
wails dev                          # Wails 热重载开发（前端 + 后端）
cd frontend && npm run dev         # 仅前端 dev server（无 Wails）
go test ./...                      # 后端测试
cd frontend && npm test            # 前端测试（vitest run）
go vet ./...                       # 后端静态检查
cd frontend && npx vue-tsc --noEmit  # 前端类型检查
```

### 构建

```bash
cd frontend && npm run build
wails build -nsis -ldflags "-s -w" -trimpath
```

### 架构门禁

```bash
powershell -ExecutionPolicy Bypass -File scripts/check-boundaries.ps1
```

校验：domain-no-upward / repo-no-upward / service-no-http / server-no-downward / harness-no-http / pkg-no-internal。

## 验收清单（改动后）

```bash
go vet ./...                       # 必须干净
go test ./...                      # 必须全绿
cd frontend && npx vue-tsc --noEmit # 必须干净
cd frontend && npm test            # 必须全绿
powershell -File scripts/check-boundaries.ps1  # 必须零违规
go build ./...                     # 必须成功
```

## 提交规范

- 提交信息用一句话说明「改了什么 / 为什么」，不要罗列文件
- 中文提交信息可接受（项目团队内部沟通）
- 大改动按 CLAUDE.md §2.5 的 JSON 字段 snake_case 等约束保持代码风格统一

## 调试技巧

| 现象 | 看哪里 |
|---|---|
| 聊天重复/卡死 | `%APPDATA%/WorkBaby/runs/{runID}.jsonl`（事件流重放） + `%APPDATA%/WorkBaby/db/workbaby.db`（消息落库） |
| 上下文超限 | harness log + `token_usages` 表 |
| 工具失败 | `message_blocks.kind=tool_result` 的 `error` 字段 + `chat:error` 事件 |
| MCP 不通 | Settings → MCP 面板 server 状态 + stderr 预览 |
| 前端构建失败 | `frontend/.vue-tsc-cache` 清理 + `node_modules/.vite` 清理 |

## 约束

- 修改代码前先 `go vet` + `npm test`，确认基线干净
- 改 harness / LLM 适配 / 工具接口这类**对外契约**时，同步更新对应 `doc/0X-*.md`
- 改数据库 schema（新增字段 / 表）：CLAUDE.md §2.11 迁移规则 + 同步 `doc/02-数据模型.md`
