# 18 · 内置运行时（Node / Python / PowerShell）

WorkBaby 安装包内嵌 Node.js / Python / PowerShell 三个运行时；用户首次启动时解压到用户目录，
后续 `tool/exec` 执行命令时前置到 PATH，不污染用户全局环境。

---

## 1. 目录模型

```
EXE 同级（安装包携带）
└── runtimes/
    ├── node-v24.18.0-win-x64.zip
    ├── python-3.12.13-win-x64.tar.gz
    ├── powershell-7.5.2-win-x64.zip
    └── manifest.json          # 版本清单（schemaVersion=2）

用户目录（首次启动解压）
└── runtimes/
    ├── node/24.18.0/         # node.exe
    ├── python/3.12.13/       # python.exe
    └── powershell/7.5.2/     # pwsh.exe
```

两级目录的理由：

| 维度 | 说明 |
|---|---|
| 安装目录只读 / 用户目录可写 | 规避权限问题 |
| 版本隔离 `{id}/{version}` | 升级不覆盖旧版 |
| 幂等启动 | 目标可执行文件已存在即跳过 |
| 隔离 | PATH 前置只对子进程生效，主进程环境不变 |

---

## 2. manifest.json 契约

```json
{
  "schemaVersion": 2,
  "platform": "win32",
  "arch": "x64",
  "assets": [
    {
      "id": "node",
      "version": "24.18.0",
      "archiveFile": "node-v24-win-x64.zip",
      "stripComponents": 1,
      "executableRelativePath": "node.exe",
      "pathDirs": ["."]
    }
  ]
}
```

字段：

| 字段 | 说明 |
|---|---|
| `id` | 运行时标识（node / python / powershell） |
| `version` | 用于目录命名与升级判别 |
| `archiveFile` | EXE 同级 `runtimes/` 下的归档文件名 |
| `stripComponents` | 解压时去掉的根目录层数（zip/tar.gz） |
| `executableRelativePath` | 解压后相对 `pathDirs` 的可执行文件路径 |
| `pathDirs` | `BinDirs()` 返回的相对目录列表，前置到 PATH |

---

## 3. 启动期解压流程（`internal/runtime`）

```
runtime.Manager.Ensure()  (启动期异步执行，不阻塞)
  ├─ 读 manifest.json
  ├─ 每个 asset：
  │   ├─ 目标 {home}/runtimes/{id}/{version}/{executableRelativePath} 存在？ → 跳过
  │   └─ 不存在：
  │       ├─ 解压 archive 到 {home}/runtimes/{id}/{version}/
  │       │   ├─ zip-slip 防护：拒绝 entry 路径含 .. 或绝对路径
  │       │   └─ 文件数 + 总字节限额
  │       └─ 标记已安装
  └─ 返回 BinDirs() = [{home}/runtimes/node/24.18.0, ...]
```

幂等 + 失败安全：
- 解压失败 → 仅记日志，下一次启动重试；
- manifest 缺失或解析失败 → 启动 fail-fast；
- 运行时被外部删除 → 启动期补回。

## 4. 执行期 PATH 注入

`internal/tool/exec` 在每次执行命令前用 `os/exec` 注入 PATH：

```go
cmd := exec.CommandContext(ctx, name, args...)
cmd.Env = append(os.Environ(), "PATH="+strings.Join(runtime.BinDirs(), string(os.PathListSeparator))+string(os.PathListSeparator)+os.Getenv("PATH"))
```

- 仅对子进程生效，主进程 PATH 不变；
- 子进程退出后环境随进程消亡，无残留；
- 不写到 `system_settings`，不跨用户/跨会话共享。

---

## 5. 工具侧的用法

`tool/exec` 接受 `command`（basename）+ `args[]`，白名单 + 危险模式正则先校验；通过后由 `executor` 在子进程 PATH 中查找。

调用示例（用户输入或 LLM 输出）：
```
command: "node"
args: ["-e", "console.log('hi')"]
```
→ 在 `{home}/runtimes/node/24.18.0/node.exe` 中运行，不会去找用户机器上的 `node`。

`tool/skillrun`（run_skill_script）使用相同 PATH 前置机制执行 Skill 内置脚本（js→node / py→python / ps1→pwsh）。

## 6. 升级与维护

| 动作 | 路径 |
|---|---|
| 升级运行时 | 改 `manifest.json` 的 `version` + 替换 EXE 同级归档；下次启动检测到版本变化自动解压到新目录，旧版本目录保留（可手动清理） |
| 删除旧版本 | 手动删除 `{home}/runtimes/{id}/{oldVersion}`；下次启动会跳过（id/version 不匹配即视为不存在） |
| 重新启用内置运行时 | 删除 `{home}/runtimes/{id}/`；下次启动自动重新解压 |
| 关闭内置运行时（用系统 PATH） | 删 `{home}/runtimes/`；`runtime.Manager.Ensure` 全部跳过，`BinDirs()` 返回空 → 工具回退到系统 PATH |

---

## 7. 排错速查

| 现象 | 检查 |
|---|---|
| `exec: "node": executable file not found` | `{home}/runtimes/node/{ver}/node.exe` 是否存在；manifest 是否损坏 |
| 工具执行返回版本不对 | 检查 manifest 是否有更高 version 目录残留，旧目录需手动清理 |
| NSIS 安装包未携带运行时 | 钩子 `scripts/copy-runtimes.ps1` 是否执行；`build/bin/runtimes/` 与 `build/windows/runtimes/` 内容是否一致 |
| 解压报 zip-slip 拒绝 | manifest 路径字段被外部篡改；重装包可解决 |
