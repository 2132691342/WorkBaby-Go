# 07 · 聊天与会话

`internal/service/chat.go` + `internal/api/api_chat.go` + 前端聊天组件：会话管理、流式主链路、消息块持久化、SSE 事件契约、审批/续跑。

## 1. 数据契约

- 会话/消息实体见 doc/02；assistant 消息的持久化过程块在 `message_blocks`（块即行、按 seq 排序），`GET .../messages` 的 MessageRESP 含 `blocks`，刷新/切会话可完整复现工具过程；无块旧历史从 `tool_calls_json` 降级重建（前端 `chat/models/blocks.ts` 唯一归一化出口）。
- 块 kind：thinking / tool_call / tool_result / artifact / genui；仅父 run 落块，子 Agent 事件不归属本消息。
- 终态统一口径：harness 终止原因经 `domain.MapHarnessReason` 映射后落库与推送（end_turn→completed 等）；前端再归一化一次，按 severity 展示横幅。

## 3. 流式发送主流程

```
POST /chat/stream
 └─ prepareRun：user 落库 + assistant 占位(streaming) + 串行化拒并发 + 登记执行平面
 └─ go runLLM（墙钟预算）：
     装配（历史→llm.Message；长期记忆/skill/压缩指示进 system 前缀）
     → harness.Runner（AutoCompressor + 重试 + 检查点 + 审批门 + 注入缝）
     → 事件经 sink 翻译为 chat:* → event.Bus → SSE
     → 终稿落库（content/thinking/tool_calls/用量/stop_reason）+ token_usages 明细 + 异步记忆形成
前端已建 GET /api/v1/events?scope=chat&runId={runId} 消费事件
```

中断/崩溃恢复：启动时 streaming 遗留消息标 `failed + stop_reason=interrupted`；前端「继续」对 interrupted 优先调 resume 端点（StepRecords 保证已完成工具不重放）。

## 4. SSE 事件契约

`GET /api/v1/events?scope=chat&runId={runId}`，事件名前缀 `chat:`：

| 事件 | 触发 | 载荷要点 |
|---|---|---|
| stream.start | run 开始（resume 带 resumed=true） | model |
| stream / thinking | 流式增量 | delta |
| stats | 每轮结束累计用量 | input/output/cache/total/latency_ms |
| tool / tool-start / tool-result | 工具三段 | id/name/arguments；result 含 content/error/duration_ms/agent（子 Agent 标签）/reused |
| subagent-start / done / error | 子 Agent 生命周期 | sub_run_id/agent/reason（**独立通道，防止假 done 关闭 SSE**） |
| approval / approval-decided | 审批与补充输入（risk=needs_approval\|irreversible\|input_required） | id/command/reason/risk |
| retry | 建流瞬时错误自动重试 | attempt/delay_ms |
| compressed | 上下文被摘要压缩 | removed_messages/summary_head |
| todo / file-change / artifact | 计划快照/文件变更/工件 | 旁路消费 |
| done / error | run 终态 | reason/stop_reason/message_id/usage；code/message |
| gap | 重放窗口失效 | 前端转权威快照拉取 |

### 可靠性套件

服务端每事件带 `id:{seq}`（RunEventLog），断线重连带 Last-Event-ID 重放缺口；30s 具名 ping 心跳；慢客户端缓冲满即断开触发重连（不丢帧）。前端 75s watchdog、500ms~8s 指数退避、`chat:gap` 转快照、rAF 批渲染、终态防御（任何异常路径不停在「正在输入」）。

## 5. 用量与上下文

- 消息级：`chat:stats` 实时驱动；历史从落库用量还原；展示 ↑输入 ↓输出 缓存命中% 耗时（人类可读；缓存为 0 不显示百分比）。
- 上下文占用单一数据源：前端 `liveContextUsage` = 权威 `/usage/context` 为基、流式期间用本轮实测 input_tokens 覆盖；顶栏环与输入框 popover 共同消费，流结束重拉权威值。

## 6. 审批与补充输入

- 审批即 run 的暂停态：未决请求落 `approval_records`（pending→approved/denied/timeout/cancelled/answered），启动排空旧 pending；needs_approval 同命令本进程免审，irreversible 每次必问；超时按拒绝（模型收结构化回执可改道）。
- `request_input` 工具：risk=input_required，审批卡切问答形态，用户回复经 `/approval/:id/answer` 回填为工具结果，run 继续。
