# 07 聊天与会话

## 定位

`internal/service/chat.go` 是聊天业务编排：发起 run、订阅 harness 事件、转发 SSE、写库、与前端 API 契约。

## 设计要点

- **一次 run 的三件事**：业务写入（消息 / 用量 / 文件变更 / 工件）+ 事件桥接（harness → SSE）+ 收尾（落库 + 推送 chat:done）
- **三种消息角色**：`user`（落库）/ `assistant`（占位 → 更新）/ `tool`（工具结果上下文重建）
- **会话分叉**：`(parent_id, branch_point)` 形成会话树；分叉复制到分叉点的消息
- **压缩预算 = 窗口 × 比例**：`ContextBudget = context_window × compression_ratio`
- **per-turn token 统计**：每轮 `chat:stats` 事件带本轮 InputTokens（前端展示上下文占比的唯一真相源）
- **占位 ID 协议**：`run_id` + `user_msg_id` + `assistant_msg_id` 一起返回，前端用 `assistant_msg_id` 做流式气泡锚点

## 关键流程

### 一次 run 的 service 侧编排

```
SendStream(req):
  1. sessions.GetByID → 取权限模式 + provider
  2. prepareRun → 写 user + assistant 占位（分配 ID）
  3. goroutine: runLLM(...) → 创建 harness.Runner → RunMessages(ctx, runID, assistantMsgID, ...)
  4. harness sink → chat.emit → bus.Publish → SSE hub → 前端
  5. runLLM 结束：UpdateStatus(content/thinking/usage/stats)
  6. doneEvent（defer）→ chat:done 到达 → safeLoadMessages({replace:true}) 拉权威快照
```

### 续跑 / 中断恢复

`ResumeRun(runID)`：从 `agent_checkpoints` 加载 msgs + state + steps → `runner.Resume(ctx, runID, ...)` → 同 runID 续推 SSE。已完成的工具步骤走 `stepRecord` 复用，不重放副作用。

崩溃恢复：`ReapInterrupted()` 启动期扫所有 `status=streaming` → 标 failed + stop_reason=interrupted；前端展示"中断"并提供"继续"按钮（用户重发 = 走正常发送链路 + 整段历史回灌，模型看得见上次做到哪儿）。

### steer 注入

`QueueSteer(ctx, sessionID, content)`：当前有活动 run 时立即落库（role=user）+ 注入队列；runner 每轮收尾前 drain 注入。本轮不打断，下一轮带上。

## 约束

- 会话消息严格按 seq 升序；`prepareRun` 用 `allocSeq` 分配与 steer 注入共享水位避免撞号
- 工具结果消息 `role=tool` 不下发到 UI（被前端 `toUiMessages` 过滤），仅供 LLM 上下文重建
- `permission_mode` 优先级：会话级 > 全局默认（`system_settings.agent.session_mode`）> 内置 `default`
- `chat:compressed` 事件在 AutoCompressor 触发时发出，前端用"上下文刚被主动压缩过"提示，避免用户对工具调用频率异常困惑
