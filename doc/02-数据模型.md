# 数据模型

后端持久化真源为单库 SQLite（pure-Go 驱动 + GORM）。DSN 开 WAL、busy_timeout、foreign_keys(ON)，连接池 `SetMaxOpenConns(1)`（单写者）。跨边界时间字段一律 int64 毫秒。

## 实体与 ID 约定

- 无公共实体基类；各表在自己的 DO 内声明主键与时间字段。
- 主键：`pkg.NewID(prefix)` → `PREFIX_<ULID>`（列存 64）。前缀常量集中在 `internal/domain/id.go`：SESSION / MESSAGE / BLOCK / PROVIDER / SKILL / MCP / DOC / CHUNK / WORKFLOW / WF_EXEC / WF_NODE / CHANNEL / CH_LOG / CRON / SPRITE / FOLDER / FILE / MEM_EPISODE / MEM_FACT / MEM_PROC。
- 另有字面前缀：run = `RUN_`、用量明细 = `USAGE_`。
- UUID v4（`NewTraceID`）仅用于跨边界 trace，不作业务主键。
- 单用户固定 `LocalUserID="local"`。

## 时间戳与软删口径（三种，勿混）

| 口径 | 判定方式 | 代表表 |
|---|---|---|
| gorm.DeletedAt | 有 deleted_at 列，GORM 默认可空过滤 | memory_episodes/facts/procedures、knowledge_docs、workflows、skills、mcp_servers |
| int64 哨兵 0 | 查询显式 `deleted_at = 0` | chat_sessions、cron_jobs、channel_configs、pet_sprites |
| 物理删 | 无 deleted_at 列 | chat_messages、message_blocks、run_records、token_usages、agent_checkpoints、files、folders、file_changes、artifacts、workflow_executions、workflow_node_executions、approval_records、channel_message_logs、ai_providers、system_settings、pet_configs、workspace_trust |

- created_at 用 `autoCreateTime:milli`、updated_at 用 `autoUpdateTime:milli`；只读聚合表（run_records 等）用手写 StartedAt/EndedAt。

## 关系与外键

- 表间为**逻辑关联**（session_id / run_id / doc_id / workflow_id / execution_id 等），各 DO **未声明外键约束**。
- 级联删除在 service / repo 显式完成，非数据库级联：删会话 → 清理 messages / message_blocks / checkpoints / run_records / artifacts；删知识库文档 → 同事务删 chunks + FTS 行（文档本身软删）。
- 会话树血缘：chat_sessions.parent_id + branch_point（分叉点 seq，根为 0），可递归。

## FTS5 虚拟表

- 四张：memory_episodes_fts、memory_facts_fts、memory_procedures_fts、knowledge_chunks_fts。
- tokenize 一律 `trigram`（固定 3 字符窗口，中文可用）；ID 列 UNINDEXED，仅正文列参与索引。
- 同步策略：主表与 FTS **同事务**写；覆盖更新走「先删后插」保无陈旧索引；知识库重索引为 delete-by-doc + 批量 INSERT。
- 检索：`MATCH` 多词按列 OR + rank/bm25 排序；trigram 对 <3 字符查询必然零命中 → 调用方回退 LIKE 子串扫描并按相关度重排。
- 建表：启动期 `CreateFTS5` 幂等（IF NOT EXISTS）；repo 首次写前惰性兜底。

## 关键不变量

- `chat_messages(session_id, seq)` 语义唯一：seq 由进程内单调分配器分配（工具结果与插话注入共用同一水位）。
- assistant(tool_calls) 与其后连续 tool 结果同进同出；重建历史时剥离孤儿 tool 与空 assistant 占位。
- `token_usages` 每次 LLM 调用一行；`total = input + output`（cache 命中是 input 的拆解维度，不叠加）；压缩摘要与委派明细 turn=-1，委派 source=delegate 并带子 Agent 名。
- memory_facts `(subject, key)` 唯一 → 覆盖更新；memory_procedures `name` 唯一 → 覆盖更新。
- agent_checkpoints `(run_id, turn)` 唯一；每 run 仅保留最新 turn。
- artifacts `(session_id, rel_path)` 唯一 → upsert；历史版本由 file_changes 快照承担。
- skills.name、mcp_servers.name 唯一。

## 迁移策略

- 启动 `db.Migrate`：AutoMigrate 全部业务表，失败即终止启动。
- FTS5 虚拟表不在 AutoMigrate 范围，由 `CreateFTS5` 单独幂等创建。
- 升级靠 AutoMigrate 的增量式加列/建表（不删既有列与数据），FTS5 用 IF NOT EXISTS 保证重复执行安全。
