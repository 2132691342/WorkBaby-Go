# 11 定时任务与通知通道

## 定位

- **定时**（`internal/cron/`）：robfig/cron/v3 包装 + 任务持久化
- **通知通道**（`internal/channel/`）：webhook / email 两种 outbox

## 定时任务

### 设计要点

- 单实例 `Scheduler`：`Start()` 起 cron runner + DB 轮询器
- 任务 CRUD 全走 `cron_jobs` 表（`enabled / spec / action_type / payload`）
- 每次执行写 `cron_executions` 审计（开始时间、结束时间、状态、错误）
- 调度节奏 = 进程内 cron + DB 联合：内存 cron 失败时不丢失（DB 兜底扫描）；内存 cron 启动后接管
- 单实例保护：Wails 单实例 + mutex（启动时如检测到其它实例运行则转交并退出，cron 不会双跑）

### 核心契约

#### CronJobDO

| 字段 | 说明 |
|---|---|
| `id` | ULID `CRONJOB_` |
| `name` | 任务名 |
| `spec` | cron 表达式（5/6 字段） |
| `enabled` | 是否启用 |
| `action_type` | `workflow`（跑工作流）/ `chat`（发消息触发 agent） |
| `payload` | action 参数（workflow_id 等） |
| `last_run_at` / `next_run_at` | 毫秒 |

#### Scheduler API

```go
type Scheduler struct {
    ...
}
func (s *Scheduler) Start() error
func (s *Scheduler) Stop() error
func (s *Scheduler) Add(job CronJobDO) error
func (s *Scheduler) Update(id string, job CronJobDO) error
func (s *Scheduler) Remove(id string) error
```

#### 触发回调

```go
type Handler func(ctx context.Context, job CronJobDO) error
```

Scheduler 在 tick 到点调 handler，handler 内部按 action_type 分发（workflow → executor / chat → sendMessage）。

## 通知通道

### 设计要点

- **两种通道**：webhook（HTTP POST，body JSON）+ email（SMTP；含 TLS）
- **outbox 模式**：`channels` 是配置，`channel_executions` 是每次发送的审计（状态 + 错误）
- **环境变量注入**：webhook 的 secret / email 密码走 `system_settings` 加密（CLAUDE.md §2.10）
- **失败重试**：网络类瞬时错误退避重试（默认 3 次指数）；业务错误（4xx）不重试

### 核心契约

#### ChannelConfigDO

| 字段 | 说明 |
|---|---|
| `id` | ULID `CHANNEL_` |
| `kind` | `webhook` / `email` |
| `name` | 用户命名 |
| `config` | webhook: `{url, secret?}` / email: `{host, port, username, password, from, to[], subject}` |
| `enabled` | 启用开关 |

#### ChannelExecutionDO

| 字段 | 说明 |
|---|---|
| `id` | ULID `CHEXEC_` |
| `channel_id` | 关联 |
| `payload` | 实际发送内容（审计用） |
| `status` | `pending` / `success` / `failed` |
| `http_status` / `error` | 响应 / 错误 |
| `attempts` | 重试次数 |
| `created_at` / `finished_at` | 毫秒 |

## 关键流程

### Webhook 发送

```
ChannelExecutor.Send(ctx, channel, payload):
  req := buildRequest(channel.config.url, channel.config.secret, payload)
  attempts = 0
  loop:
    attempts++
    resp, err := http.Do(req)
    if err and attempts < 3 and isTransient(err): backoff(2^attempts); continue
    recordExecution(status, http_status, error)
    return
```

### Email 发送

SMTP via `net/smtp`（starttls / ssl）；失败重试同 webhook。

### 失败降级

`status=failed` 写库后给用户 toast 提示；不阻塞 agent run（通道是 fire-and-forget）。

## 约束

- 所有密钥字段（webhook secret / email password）AES-GCM 加密落库（CLAUDE.md §2.10）
- Scheduler tick 在 goroutine 中运行；handler 异常吞掉不崩 scheduler（但写 execution 审计）
- 通知发送超时（默认 10s）独立于 cron tick；不阻塞下一次调度
