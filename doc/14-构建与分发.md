# 构建与分发

仅面向 Windows（amd64）。产物为单个可执行文件 + 内置运行时归档，安装包由 NSIS 生成。

## 前置条件

- Go 1.25.x
- Node.js（前端构建）
- Wails CLI v2（`wails` 命令）
- NSIS（生成安装器；`choco install nsis -y` 或官网安装）

## 构建命令

```bash
# 完整构建（含 NSIS 安装器）——发布用
wails build -clean -platform windows/amd64 -trimpath -nsis

# 仅可执行文件（不含安装器）——本地快速调试
wails build -platform windows/amd64 -trimpath
```

**`-nsis` 必填才能产出安装器**：wails 源码 `cmd/wails/build.go` 里只有 `if f.NSIS` 才调用
`GenerateNSISInstaller`；缺了它不会生成 `WorkBaby-amd64-installer.exe`（且不报错，静默跳过）。
另：若 PATH 中找不到 `makensis`，NSIS 生成会打印 warning 并静默跳过，同样不产出安装器。

## 构建配置（`wails.json`）

| 项 | 值 | 说明 |
|---|---|---|
| name / outputfilename | WorkBaby | 产物名 `WorkBaby.exe` |
| frontend:install / build | `npm install` / `npm run build` | 构建前自动装依赖并打包前端 |
| frontend:dev:watcher | `npm run dev` | 开发模式前端热更新 |
| wailsjsdir | ./frontend/src | Wails 绑定生成位置 |
| productVersion | 0.1.0 | 应用版本（`/meta/version` 来源之一） |
| fileAssociations | md / txt / pdf | 安装器注册的文件关联 |
| postBuildHooks | `../../scripts/copy-runtimes.ps1 ${bin}` | 构建后复制内置运行时（见下方约束） |

### postBuildHook 路径约束（Wails CLI 源码决定）

Wails 在 `pkg/commands/build/build.go:executeBuildHook` 中：

1. **cwd = `build/bin`（`options.BinDirectory`），不是项目根** —— 所以用 `../../scripts/...`；
2. **hook 字符串经 `shlex.Split` 解析**，反斜杠被当转义符吃掉 —— 必须用正斜杠 `/`；
3. **`${bin}` 只在作为独立参数时才被替换**（按整个 arg 精确匹配）—— 不能拼成 `${bin}\..\..\scripts\...`。

## 内置运行时

`runtimes/` 目录为源：`manifest.json` + 每个资产一个归档。

| 资产 | 归档 |
|---|---|
| Node.js | node v24.18.0 win-x64（zip） |
| Python | python 3.12.13 win-x64（tar.gz） |
| PowerShell | powershell 7.5.2 win-x64（zip） |

- 构建后置钩子把 `runtimes/` 复制到 `<binDir>/runtimes` 与 `<buildDir>/windows/runtimes`（后者供 NSIS 打包）；manifest 中声明的归档缺失时**构建直接失败**，不会产出缺运行时的安装包。
- 运行时在应用首启解压到 `{home}/runtimes/{资产}/{版本}`，其 bin 目录前置到子进程 PATH（脚本执行、MCP server 均受益），无需用户预装。

## 构建产物

| 产物 | 位置 | 入库 |
|---|---|---|
| 可执行文件 | `build/bin/WorkBaby.exe` | ❌（.gitignore 忽略） |
| 运行时副本 | `build/bin/runtimes/` | ❌ |
| 安装程序脚本 | `build/windows/installer/project.nsi` | ✅（NSIS 源码） |
| NSIS 安装器 | `build/bin/WorkBaby-amd64-installer.exe` | ❌（走 GitHub Release） |

前端产物在构建阶段由 `npm run build` 生成并**嵌入二进制**，运行时通过 Wails AssetServer 提供；`/files/**` 路径映射到受管文件服务，其余路径回落到嵌入的前端资源。

## 自动发布（GitHub Actions）

`.github/workflows/release.yml`：推送形如 `v0.1.0` 的 tag 时自动跑完整流水线并发布 GitHub Release。

```
git tag v0.1.0
git push origin v0.1.0
# → GitHub Actions 自动：
#   1) checkout（含 LFS 拉 runtimes 归档）
#   2) 装 Go 1.25 / Node 20 / Wails CLI / NSIS
#   3) wails build（前端 npm ci → 嵌入 → NSIS 打包成 installer.exe）
#   4) 上传 build/bin/WorkBaby-amd64-installer.exe 到 Release + 自动生成 release notes
```

**门禁**：`scripts/test.ps1 -Full`（核心包测试 + 分层依赖方向 + 前端类型 + 单测）必须全绿才允许出包。

**手动触发**：在 GitHub Actions 页面 Run workflow（不传 tag）可测试流水线，**产物上传为 Actions artifacts 而非 Release**，避免污染正式渠道。

**失败排查**：构建失败时保留 `build/bin/` 为 7 天 artifacts（不含 `runtimes/` 节省空间），本地下载解压后可直接 `WorkBaby-amd64-installer.exe` 复现。

**为什么不在仓库入库**：
- NSIS 安装器每次构建嵌入时间戳/版本 → LFS pointer 必变 → `git status` 永远 modified
- 二进制不可 diff/code review → 入库即负担
- GitHub Release 提供完整的下载统计 / 校验和 / 历史版本管理

## 数据目录与卸载

- 数据根 `{home}`：默认 `%APPDATA%\WorkBaby`，可用环境变量 `WORKBABY_HOME` 覆盖（便于多实例/便携部署）。
- 应用数据（库、日志、配置、记忆、快照、技能、运行时、受管文件）全部在 `{home}` 下，卸载程序不主动删除；工作区沙箱在用户绑定的工作目录内（`.workbaby/`）。

## 门禁脚本

| 脚本 | 用途 |
|---|---|
| `scripts/test.ps1` | 分层测试入口（核心包 / 全量 / 单包）；CI 流水线用 `-Full` |
| `scripts/check-boundaries.ps1` | 单独跑分层依赖方向与契约版本校验 |
| `scripts/copy-runtimes.ps1` | 构建后复制内置运行时并校验归档完整性 |

## 常见失败点

- `runtimes/manifest.json` 与实际归档不一致 → 构建 fail fast。
- 前端 `npm install` / `npm run build` 失败 → 整个构建中断（先单独跑通前端构建更易定位）。
- 依赖方向或契约版本不一致 → `test.ps1 -Full` 报错，需先修复再打 tag。
- Tag 推送后 CI 失败 → 检查 Actions 日志；失败产物已自动作为 artifacts 上传。
