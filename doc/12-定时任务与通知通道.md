# 12 · 定时任务与通知通道

`internal/cron/`（Cron 调度）与 `internal/channel/`（多通道通知）两个并列模块，
构成「到点干活 + 干完说一声」的自动化闭环。两者均不依赖 Wails runtime，可独立单测。

---

## 设计

| 模块 | 职责 | 持久化 |
|---|---|---|
| cron | 表达式调度 + 动作触发 + 增删改热更新 + 手动触发 | `cron_jobs` 表 |
| channel | 多通道出站投递 + 通道生命周期 + 发送日志 | `channel_configs` / `channel_message_logs` |

动作处理器与通道适配器都是注册制扩展点，调度器与发送服务本身不认识具体业务。

## 核心契约

### cron_jobs

| 字段 | 说明 |
|---|---|
| `id` / `name` | 主键 / 任务名 |
| `spec` | Cron 表达式（robfig/cron standard 格式，落库前 `ParseStandard` 校验） |
| `action` / `action_args` | 动作类型 / JSON 参数（`run_workflow` 为 `{"workflowID": ...}`） |
| `enabled` | 是否参与调度（软删走 `deleted_at`） |
| `last_run_at` / `last_status` | 最近执行时间 / `success` · `failed` |
| `next_run_at` | 下次触发时间，由 `Schedule.Next` 计算后回写 |

动作类型与 handler 注册（装配层 `api/handler.go`）：

| 动作 | 注册行为 |
|---|---|
| `run_workflow` | `RegisterHandler` 注入：解析 `actionArgs` → 调 workflow service `Run(workflowID)` |

`RegisterHandler(action, handler)` 为通用扩展点，动作类型的增减只发生在装配层。

### 通知通道

```go
type Channel interface {
    Type() domain.ChannelType
    Send(ctx, config *ChannelConfigDO, msg *Message) error
    Validate(config *ChannelConfigDO) error // 配置完整性自检，不真实拨测
}
```

| 类型 | 实现 | 要点 |
|---|---|---|
| `EMAIL` | 标准库 `net/smtp` | SMTP 服务器配置来自 `system_settings`（密码加密落库、发送前解密、端口缺省 587）；收件人取 `configJson.to`；缺省 subject 为 `WorkBaby: {sessionId}` |
| `WEBHOOK` | HTTP client（30s 超时） | `configJson`：`url` / `method`（仅 GET/POST，缺省 POST）/ `headers` / `auth`（bearer·basic）；body 固定 JSON `{subject, body, contentType, sessionID}`；非 2xx 记失败 |
| `CONSOLE` | 应用日志 | 兜底通道，`Validate` 恒通过 |

- `channel_configs`：`channel_type` / `enabled` / `config_json` / `status`（`stopped`·`running`）/ `last_error` / `last_active_at`；
- `channel_message_logs`：每次发送一条，`direction=outbound`，`content_summary` 截断 200 字，
  状态流转 `pending → success | failed`（失败记 `error_message`，截断 500 字）；
- `contentType` 由消息类型映射：`markdown`→text/markdown，`html`→text/html，其余 text/plain；
- 创建/更新请求的结构化字段（`email_to` / `webhook_url`）可兜底组装 `config_json`。

## 关键流程

**调度**：

```
Start()       加载全部 enabled 任务逐个入调度（单任务失败仅告警不阻断）→ cron.Start()
Create/Update 表达式校验 → 落库 → enabled 则重新入调度，否则移除 entry
Trigger       立即异步执行一次，与到点触发共用同一 handler
execute       10 分钟超时 ctx → 执行动作 → 回写 last_run_at / last_status
```

**发送**（`Service.Send`，即工作流 ChannelSender 的实现）：

```
查通道配置 → 未启用拒绝 → 按类型取适配器 → 落 pending 日志 → Send → success / failed 回写，返回 logID
```

发送上游：工作流 channel 节点、手动触发；`Test` 只跑 `Validate` 配置自检。

## HTTP 接口

| 接口 | 方法 · 路径 |
|---|---|
| 任务列表 / 新建 | GET · POST `/api/v1/cron/jobs` |
| 更新 / 删除 / 触发 | POST `/api/v1/cron/jobs/{id}/update` · `/delete` · `/trigger` |
| 通道列表 / 新建 | GET · POST `/api/v1/channels` |
| 更新 / 删除 | POST `/api/v1/channels/{id}/update` · `/delete` |
| 启动 / 停止 / 自检 | POST `/api/v1/channels/{id}/start` · `/stop` · `/test` |
| 消息日志 | GET `/api/v1/channels/{id}/messages?limit=` |

## 错误码

| Code | 含义 |
|---|---|
| 9201 | 表达式无效 / name·schedule 缺失 |
| 9202 | 动作类型未知 / run_workflow 缺 workflowId |
| 9204 | 任务不存在 |
| 9301 | webhook 发送失败（非 2xx / 请求错误） |
| 9303 | SMTP 未配置或发送失败 |
| 9304 | 通道不存在 / 未启用 / 类型未注册 |
| 9305 | 通道配置无效（缺收件人 / 缺 url / method 非白名单） |

## 约束

- 调度与发送均只认注册表，能力域不反向依赖业务层；
- 单次任务执行超时 10 分钟；单任务失败不影响其他任务；
- 通道 `Test` 是配置自检不做网络拨测，真实投递结果以 `channel_message_logs` 为准；
- HTTP 仅 GET/POST，路径变量在末尾，body 字段 snake_case。
