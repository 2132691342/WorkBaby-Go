# 项目概览

## WorkBaby 是什么

一个跑在 Windows 桌面端的个人 AI 助手。它不是网页套壳：后端是一个完整的 Go 应用，能读写用户工作区里的文件、执行命令、跑脚本、访问外部 MCP 工具源，并把所有过程数据（记忆、快照、产出物）管理在自己的目录体系里。所有数据落本机，不依赖任何云端账号体系。

## 能力清单

| 能力域 | 说明 |
|---|---|
| 对话 | 多会话、流式回复、思维链分离、中途插话（steer）、排队入队、断线续跑 |
| 工具执行 | 文件读写、命令执行、网页抓取、搜索、纯函数工具集、文档解析、归档 |
| 记忆 | 情景 / 语义 / 程序三类记忆自动沉淀 + 长期记忆（MEMORY.md）+ 跨会话召回 |
| 知识库 | 本地文档导入 → 分块 → FTS5 全文索引 → 检索注入上下文 |
| 技能 | SKILL.md 协议的技能包：说明 + 允许工具 + 可执行脚本，按输入自动匹配 |
| MCP | 外部 MCP server 作为工具源，stdio 子进程托管，热重载 |
| 工作流 | 可视化 DAG：LLM / 工具 / 代码 / 条件 / HTTP / 人工输入 / 通知 七类节点 |
| 自动化 | 定时任务（cron）驱动工作流，结果经邮件 / Webhook / 控制台通道通知 |
| 后台任务 | 长任务进队列异步执行，任务中心实时看进度与结果 |
| 桌宠 | 独立置顶小窗形态 + 聊天页悬浮陪伴体，形象可裁剪 / 旋转 / 抠图 |
| 可观测 | token 用量（含缓存命中）、执行记录、事件 JSONL 导出、仪表盘 |

## 技术选型

| 层 | 技术 | 为什么 |
|---|---|---|
| 语言 | Go 1.25 | 单二进制分发、并发模型适合「多会话 + 多工具并行 + 后台队列」的负载形态 |
| Web 框架 | Gin | 业务 API 走 HTTP，路由分组与中间件成熟 |
| ORM / 存储 | GORM + SQLite | 本地单用户，零部署；FTS5 提供全文检索能力 |
| 桌面壳 | Wails v2 | 系统能力（对话框 / 托盘 / 窗口控制）走 Go 绑定，前端仍是标准 Web 技术 |
| 前端 | Vue 3 + TS + Vite + Element Plus + Tailwind | 组件生态 + 类型安全 + 快速构建 |
| 文档解析 | 内置解析器 + 按需外部依赖 | Markdown / PDF / Office 常规格式开箱可用 |

## 架构优势

1. **双主机**：业务 API 走 gin HTTP（127.0.0.1 随机端口），系统能力走 Wails 绑定。前端与业务后端彻底解耦，前端可以独立开发、独立测试，业务逻辑不依赖桌面壳。
2. **单一执行平面**：聊天、工作流、定时任务、后台任务都走同一个 harness 执行器与统一的事件协议（`chat:*` / `task:*` / `workflow:*`），新增一种「让 Agent 干活」的入口不需要重写执行逻辑。
3. **能力注册表**：人格、工作区、记忆、知识库、技能、工作流都是实现同一个 `Capability` 接口的插件，按序注入 system 上下文，run 结束后统一沉淀。扩展能力只加一个文件。
4. **工具即契约**：所有工具实现统一 schema 与风险分级，执行前过同一道审批门；白名单外的命令必须用户确认，且审批可持久化、可恢复。
5. **本地优先**：SQLite 单文件 + 目录约定（见 02），备份 = 拷贝目录；工作区过程数据全部收进 `.workbaby/`，不污染用户项目。
