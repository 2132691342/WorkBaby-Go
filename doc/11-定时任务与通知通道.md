# 定时任务与通知通道

位置：`internal/cron/`（调度）+ `internal/channel/`（通知）。

## 定时任务

- 存储：`cron_jobs` 表（cron 表达式 + 动作 + 参数 + 启停）。
- 调度：进程内 Scheduler，启动时加载全部 enabled 任务注册到调度器；表达式非法或时区异常只告警不阻断启动。
- 触发精度为分钟级；支持手动触发（`/cron/:id/trigger`）与上下次执行时间回显。

### 动作模型

动作以 `type + args(JSON)` 描述，当前支持：

| 动作 | 参数 | 行为 |
|---|---|---|
| `run_workflow` | `workflowId` | 触发指定工作流执行 |

动作处理器在启动时注册（`RegisterHandler`），新增动作类型只需实现一个 handler 并注册，调度器与页面无需改动。

## 通知通道

### 通道抽象

```go
type Channel interface {
    Name() string
    Send(ctx context.Context, message OutboundMessage) error
}
```

内置实现：

| 通道 | 说明 |
|---|---|
| `email` | SMTP 发信；配置经加密存储，发送前可连通性测试 |
| `webhook` | POST JSON 到自定义地址 |
| `console` | 落日志（调试与兜底） |

### 配置与日志

- 每个通道一行配置（enabled + 凭据），凭据 AES-GCM 加密，列表接口返回脱敏值。
- 每次发送写 `channel_message_logs`（通道 / 收件人 / 内容摘要 / 成败 / 错误），页面可查发送历史，排障不靠猜。

### 与工作流的组合

工作流的 `channel` 节点从 `channel.Service` 取发送能力；典型组合是「定时任务 → 工作流（采集 + LLM 汇总）→ 邮件通知」，构成无人值守的自动化闭环。

## 失败语义

- 任务触发失败：记录执行失败原因，不影响调度器继续运行。
- 通道发送失败：只记日志与返回错误，不阻断工作流（`channel` 节点可配置是否把发送失败视为工作流失败）。
