# 聊天与会话

## 会话模型

`chat_sessions`：id、user_id（单用户固定 local）、provider_id + model（本会话使用的模型）、workspace_id + workspace_path（绑定的外部工作目录）、status（active / archived）、message_count、last_message_at、permission_mode（restricted / default / auto_edit / yolo；空 = 跟随全局）、parent_id + branch_point（会话树血缘，分叉点 seq）、metadata_json（压缩归档摘要与压缩指示）、时间戳。

- 分叉：`POST /chat/messages/:sid/fork` 把「到某条消息为止」的对话复制成新会话并记录父会话与分叉点，原会话不变。
- 工作区绑定：绑定后文件工具沙箱、快照、记忆落点、exec cwd 全部跟随该目录；未绑定回落到 `{home}/workspaces/{sessionID}` 隔离区。

## 消息模型

`chat_messages`：id、session_id、seq、run_id、role（user / assistant / tool / system）、content、thinking（思维链，独立字段）、tool_call_id、tool_calls（JSON）、attachments_json（附件：图片 / 文件，含受管文件 id、mime、大小、直读 URL）、status（pending / streaming / completed / failed / cancelled / archived）、stop_reason、model、input/output/cache_read/total_tokens、latency_ms、cost。

## 多模态附件

- **入口**：三条路径——文件对话框选择、拖拽、粘贴图片。后两者拿到的是内存字节（没有本地路径），走 `POST /files/upload-data` 落入受管目录并返回 `FileInfo`。
- **落库**：发送时 `POST /chat/stream` 带 `file_ids`，解析为附件元信息写入 `chat_messages.attachments_json`；正文保持纯文本，附件与正文分离，附件内容存 `{home}/files/{id}`。
- **送模型**：仅**最后一条用户消息**的图片附件转成多模态 part，按上游协议展开——OpenAI `content[]` 的 `image_url`（data URI）、Anthropic `source.base64`、Ollama 消息级 `images`（裸 base64）。历史轮次的图片降级为文本附件行，避免老图反复计入 token。
- **降级**：`supports_vision` 三态判定（显式声明 > 模型名推断）为 false 时，图片不进多模态通道，统一降级为文本附件行，模型至少知道用户附了什么。
- **渲染**：用户气泡内联缩略图，点击原窗口查看；刷新与切会话后仍可回看。

## 文件变更与内联 diff

- **记录**：写类工具（写文件 / 编辑）在工具层生成变更快照（before / after），service 落 `file_changes` 表并按 run 推 `chat:file-change`；若写入落在会话工作区 `.workbaby/` 之外，额外推 `chat:warn`（污染用户原有目录，强制提示清理）。
- **呈现**：变更直接长在消息流里（`InlineDiffCard`），折叠态一行给出「动作 + 路径 + 增删行数」，展开时按需拉 `GET /chat/changes/:id` 渲染着色 diff，并可就地回滚（`POST /chat/changes/:cid/rollback`）。
- **口径**：变更列表接口不返回 diff 正文，只返回增删行数与字节变化，避免一次会话拉几十份全文。

- **seq 分配**：进程内单调分配器统一给 user、assistant、tool 结果与插话注入分配，保证增量分页游标不漏消息。
- **归档**：`/compact` 把早期轮次置 archived（内容仍落库、UI 可见），并在会话元数据写归档摘要，下一轮注入 system。

`message_blocks`：过程块的持久化（kind：thinking / tool_call / tool_result / artifact / genui / skill），按 seq 排序；刷新或切会话后历史消息可完整回放执行过程。

## 流式发送全链路

```
POST /chat/stream               建 run（分配 run_id + 两条消息 seq + assistant 占位 streaming）
GET  /events?scope=chat&runId=…  SSE 订阅（Last-Event-ID 重放 + ping 心跳）
POST /chat/stream/:id/cancel    中断
POST /chat/stream/:id/resume    从检查点续跑（同一 run_id，已完成工具不重放）
POST /chat/sessions/:id/steer   run 中插入指令（下一轮或收尾前生效）
```

## 块序列渲染（按事件到达顺序）

`message_blocks` 表存的是**按 seq 排序的稳定块序列**：`thinking → tool_call / tool_result → artifact / skill / genui` 真实穿插（不是按维度分组）。

后端事件顺序：`chat:thinking → chat:stream → chat:tool → chat:tool-start → chat:tool-result`，每条事件经 `chat.go:persistBlock` 按 `blockSeq++` 单调递增落 message_blocks；前端 `ChatStreamDecoder.decodeStreamEvent` 按事件到达顺序同时维护：
- **旧字段**（兼容）：`streamingContent / streamingThinking / streamingTools / streamingSkill`
- **新字段**（真相源）：`streamingBlocks: StreamingBlock[]`，由 `chat/models/streamingBlocks.ts:applyBlockUpdate` 维护；同类连续合并（连续正文 delta 累计、连续 tool_result 按 tool_call_id 合并）。

前端组件：
- `MessageBlocksRenderer.vue` 同时接受 `ResolvedBlock[]`（历史）与 `StreamingBlock[]`（流式），按数组顺序渲染；text 块通过 slot 让外层接 MarkdownRenderer + 光标。
- `MessageItem.vue` 用 MessageBlocksRenderer 替代 TaskTimeline + MarkdownRenderer（历史消息）。
- `StreamingBubble.vue` 用 MessageBlocksRenderer 替代 TaskTimeline + MarkdownRenderer（流式期间）；光标挂在最后一条 text 块。

流式结束时 `finalizeStreamingMessage` 把 `streamingBlocks` 转为 MessageBlock 形状写入消息（chat:done 先于落库的窗口期兜底）。

- 可靠性：`Last-Event-ID` 重放、内存环形缓冲被覆盖时下发 `chat:gap` 转全量快照、双看门狗（全静默 / 仅心跳）判定假死后指数退避重连、整轮总超时兜底。
- 终态：`chat:done` 在 assistant 消息落库**之后**发出，前端收到后拉权威快照；停止原因归一为 completed / cancelled / max_turns / stagnation / token_budget / error，可恢复终态给「继续」入口。

## 审批与后台任务

- 审批：工具策略门 ask → `chat:approval` 事件阻塞等待 → 前端三选一（批准 / 本会话允许 / 拒绝）→ `chat:approval-decided`。不可逆操作每次必问；未决请求落库，刷新后经 `GET /chat/approvals/pending` 恢复；启动时把遗留 pending 标 cancelled。补充输入（input_required）走 `/chat/approval/:id/answer`。
- 后台任务：`POST /tasks` 提交（有界 worker 池执行长任务），`GET /tasks`、`GET /tasks/:id`、`POST /tasks/:id/cancel`；任务中心实时显示进度与结果。

## 上下文占用透视

`GET /chat/sessions/:id/usage/context` 返回分段占用：system（含记忆注入）/ 工具定义 / 历史消息，各段有 token 数与千分比；历史段优先取末条 assistant 的实测 input_tokens，拿不到则按字符估算并标注估算。分段口径与真实请求同一装配入口，保证「用户看到的占用」与「实际发送」一致。

## 不变量

- 同一会话同时只有一个活动 run；重复续跑返回明确错误。
- `(session_id, seq)` 语义唯一，工具结果与插话注入也走同一分配器。
- assistant(tool_calls) 与 tool 结果配对完整；回发上游前剥离孤儿 tool 与空 assistant 占位。
- 每轮 LLM 调用用量单独落 `token_usages`，消息上的用量是末轮汇总。
