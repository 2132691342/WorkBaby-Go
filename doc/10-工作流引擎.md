# 10 · 工作流引擎

定义 `internal/workflow/`：图模型、分支路由与汇合、执行器、节点类型、Vue Flow 可视化编辑器契约。

---

## 1. 两层数据形态

工作流定义以 **Graph JSON** 落库（`workflows.graph`），可视化编辑器通过 **DAG wire 格式**与后端交换，service 层负责双向转换：

```text
Graph JSON（持久化）
  { name, inputs?, nodes:[{id,type,deps,config,pos?}], outputs? }

DAG wire（前端 ⇄ 后端）
  { name, nodes:[{id,type,params,branch?,pos?}], edges:[{from,to,source_handle?}], outputs? }
```

| Graph JSON | DAG wire | 说明 |
|---|---|---|
| `nodes[].config` | `nodes[].params` | 节点参数 |
| `nodes[].deps` | `edges[]` | 依赖边 |
| `nodes[].branch` | 指向 condition 源边的 `source_handle` | condition 分支归属 |
| `nodes[].pos` | `nodes[].pos` | 画布坐标（持久化，执行忽略） |
| `graph.outputs` | `outputs` | 图级输出：`key → "nodeId.field"` |

可视化保存（`POST /workflows/:id/update-graph`）与加载（`GET /workflows/:id/graph`）双向无损转换；文本编辑器直接编辑 Graph JSON。

## 3. 节点抽象

```go
type Node interface {
    Type() domain.WorkflowNodeType
    Execute(ctx, inputs, cfg, upstream map[string]any) (map[string]any, error)
    Schema() Schema
}

type FieldSpec struct {
    Name        string
    Label       string
    Type        FieldType  // text / number / textarea / select / json
    Required    bool
    Description string
    Options     []string
    Default     any
}
```

- **Schema 单一来源**：FieldSpec 同时驱动前端属性面板、必填校验、默认值；
- `GET /api/v1/workflows/node-types` 返回 7 类节点及其字段（前端调色板/属性面板数据源）。

| 节点 | Type | 必填 config | 输出 |
|---|---|---|---|
| LLM | llm | providerID / model | {text, usage, providerID} |
| Tool | tool | toolName | 工具执行结果 |
| Code | code | script | **goja 沙箱**：纯 JS 运行时（无 require/fs/network）；全局 `$input` 为上游输出，结果写全局 `output` 或末表达式返回；`timeout_ms` 默认 10s 上限 60s，超时/取消走 vm.Interrupt |
| HTTP | http | url（method 仅 GET/POST） | {status, body, headers} |
| Condition | condition | expression（expr-lang/expr） | {branch} |
| HumanInput | human_input | prompt | 阻塞等前端回执 → {value} |
| Channel | channel | channelID / messageType | 通道投递结果 |

## 4. 分支路由与汇合

**符号化路由（条件分支）**：
- condition 节点输出 `branch`（bool → `true`/`false`，字符串原样作为分支标签）；
- 从 condition 源连出的边带 `source_handle`，保存时写入目标节点 `branch`；
- 目标节点在 `Deps` 中查找上游 condition 节点，按其输出分支与自身 `branch` 决定是否激活。

**分支跳过传播与汇合活性判定**：
1. 自身 branch 不命中 → 跳过；
2. 无上游 → 恒运行；
3. 全部上游被跳过 → 整条路径不成立，**跳过传播**给下游；
4. 至少一路存活（执行成功或为 condition 节点）→ 运行。

- 汇合节点（多 dep）只要任一上游存活即运行：condition 恒执行，可作为分支汇合点回归主流程。
- 跳过态写入 `workflow_node_executions`（Status = skipped），不落 inputs / outputs。

校验器拒绝「声明 branch 但无 condition 上游」的图（执行期会被静默跳过）。

## 5. Executor

```
Kahn 拓扑分层 → 逐层执行 → 层内节点并行 → 首错误快速失败
  ├─ 全程落 workflow_executions / workflow_node_executions
  ├─ 层边界支持暂停 / 恢复 / 取消
  ├─ 结束按 graph.outputs 提取最终结果落库
  └─ 终态由 Run 流程单一写入者收尾
```

| 操作 | 端点 |
|---|---|
| 手动运行 | POST `/api/v1/workflows/:id/run` → `{execution_id}` |
| Cron 触发 | cron_jobs.action = run_workflow |
| 执行详情 | GET `/api/v1/executions/:id` → `{execution, nodes[]}`（前端轮询 + 画布高亮） |
| 控制 | POST `/api/v1/executions/:id/pause` / `resume` / `cancel` / `input` |

## 6. 校验器

1. 节点 ID 唯一且合法（`^[a-z][a-z0-9_]*$`）
2. deps / inputs / outputs 引用存在
3. 拓扑分层检测环 → 9103
4. 必填配置齐全 → 9104
5. branch 必须有 condition 上游 → 9104

保存时校验一次，执行前再校验一次。

## 7. 可视化编辑器

`WorkflowGraphView.vue` + Vue Flow：

- 左侧调色板 = node-types 目录（7 类真实节点）；右键节点连边；
- condition 节点渲染 **T/F 双出口 handle**，连线携带分支；
- 属性面板按节点类型渲染 schema 表单（provider / tool 用真实列表下拉）；
- 节点坐标拖拽后写入 `pos` 持久化；侧栏「图输出」编辑区管理 `outputs` 映射；
- 运行中画布按节点执行状态高亮：RUNNING（主色外圈）/ COMPLETED / FAILED / SKIPPED。
