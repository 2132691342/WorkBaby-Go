# 聊天与会话

## 会话模型

`chat_sessions`：id、user_id（单用户固定 local）、provider_id + model（本会话使用的模型）、workspace_id + workspace_path（绑定的外部工作目录）、status（active / archived）、message_count、last_message_at、permission_mode（restricted / default / auto_edit / yolo；空 = 跟随全局）、parent_id + branch_point（会话树血缘，分叉点 seq）、metadata_json（压缩归档摘要与压缩指示）、时间戳。

- 分叉：`POST /chat/messages/:sid/fork` 把「到某条消息为止」的对话复制成新会话并记录父会话与分叉点，原会话不变。
- 工作区绑定：绑定后文件工具沙箱、快照、记忆落点、exec cwd 全部跟随该目录；未绑定回落到 `{home}/workspaces/{sessionID}` 隔离区。

## 消息模型

`chat_messages`：id、session_id、seq、run_id、role（user / assistant / tool / system）、content、thinking（思维链，独立字段）、tool_call_id、tool_calls（JSON）、attachments_json（附件：图片 / 文件，含受管文件 id、mime、大小、直读 URL）、status（pending / streaming / completed / failed / cancelled / archived）、context_scope（llm / ui；ui = 仅界面可见，不进 LLM 上下文）、stop_reason、model、input/output/cache_read/total_tokens、latency_ms、cost。

**消息分层**：`context_scope=ui` 的消息可完整落库并在界面回放，但不参与上下文装配（判定入口 `service.includeInLLMContext`，与归档轮次、streaming 占位同源）。取消/崩溃残段的悬挂 tool_calls（发起了调用但结果未落库）在上下文重建时剥离——tool_use 无对应 tool_result 上游必 400；半截正文保留，中断后续聊叙事不断裂。

**结构化状态（三层 State）**：`session_variables` 保存跨轮次的结构化状态，与「会话计划（todo）」分工——plan 描述步骤与进度，变量承载上下文。作用域三层：

| 作用域 | 落点 | 生命周期 | 用途 |
|---|---|---|---|
| `user` | `session_id = "__user__"` 哨兵 | 跨会话长期 | 用户偏好、称呼、常用目录 |
| `session`（默认） | 真实会话 ID | 会话内 | 当前处理对象、约定标识 |
| `temp` | 进程内 `runID → map` | 本轮 run（结束即清） | 临时草稿，不落库 |

注入时按 `[用户级] / [会话级] / [本轮临时]` 分节渲染（低优先级）；由 `session_var` 工具（含 `scope` 参数）与 `GET/POST /chat/sessions/:id/vars` 读写；写入有规模上限（key ≤128、值 ≤2000、每个作用域数量 ≤50），因为内容会进 system 段。`temp` 拒走持久化路径，只能经 run 上下文写入。

## 多模态附件

- **入口**：三条路径——文件对话框选择、拖拽、粘贴图片。后两者拿到的是内存字节（没有本地路径），走 `POST /files/upload-data` 落入受管目录并返回 `FileInfo`。
- **落库**：发送时 `POST /chat/stream` 带 `file_ids`，解析为附件元信息写入 `chat_messages.attachments_json`；正文保持纯文本，附件与正文分离，附件内容存 `{home}/files/{id}`。
- **送模型**：仅**最后一条用户消息**的图片附件转成多模态 part，按上游协议展开——OpenAI `content[]` 的 `image_url`（data URI）、Anthropic `source.base64`、Ollama 消息级 `images`（裸 base64）。历史轮次的图片降级为文本附件行，避免老图反复计入 token。
- **降级**：`supports_vision` 三态判定（显式声明 > 模型名推断）为 false 时，图片不进多模态通道，统一降级为文本附件行，模型至少知道用户附了什么。
- **渲染**：用户气泡内联缩略图，点击原窗口查看；刷新与切会话后仍可回看。

## 文件变更与内联 diff

- **记录**：写类工具（写文件 / 编辑）在工具层生成变更快照（before / after），service 落 `file_changes` 表并按 run 推 `chat:file-change`；若写入落在会话工作区 `.workbaby/` 之外，额外推 `chat:warn`（污染用户原有目录，强制提示清理）。
- **呈现**：变更直接长在消息流里（`InlineDiffCard`），折叠态一行给出「动作 + 路径 + 增删行数」，展开时按需拉 `GET /chat/changes/:id` 渲染着色 diff，并可就地回滚（`POST /chat/changes/:cid/rollback`）。
- **口径**：变更列表接口不返回 diff 正文，只返回增删行数与字节变化，避免一次会话拉几十份全文。

- **seq 分配**：进程内单调分配器统一给 user、assistant、tool 结果与插话注入分配，保证增量分页游标不漏消息。
- **归档**：`/compact` 把早期轮次置 archived（内容仍落库、UI 可见），并在会话元数据写归档摘要，下一轮注入 system。

`message_blocks`：过程块的持久化（kind：**text** / thinking / tool_call / tool_result / artifact / genui / skill），按 seq 排序；刷新或切会话后历史消息可完整回放执行过程。

`text` 块是**正文片段**：`runEventMapper` 累积 content 增量，在「工具调用之前」与「轮次/run 结束」两处落块，因此块的 seq 顺序 = 模型真实的输出顺序（叙述 → 工具 → 叙述）。早期实现不落 text 块、只在渲染时把 `message.content` 补到末尾，结果是刷新后所有叙述都被挤到过程之后——顺序与流式期不一致。`message.content` 仍保存全文，供复制 / 编辑重发 / 导出 / 分叉使用；前端仅在块序列内**没有** text 块时才补一次 `content`（兼容旧数据）。

## 流式发送全链路

```
POST /chat/stream               建 run（分配 run_id + 两条消息 seq + assistant 占位 streaming）
GET  /events?scope=chat&runId=…  SSE 订阅（Last-Event-ID 重放 + ping 心跳）
POST /chat/stream/:id/cancel    中断
POST /chat/stream/:id/resume    从检查点续跑（同一 run_id，已完成工具不重放）
POST /chat/sessions/:id/steer   run 中插入指令（下一轮或收尾前生效）
```

## 块序列渲染（按事件到达顺序）

`message_blocks` 表存的是**按 seq 排序的稳定块序列**：`thinking → tool_call / tool_result → artifact / skill / genui` 真实穿插（不是按维度分组）。

后端事件顺序：`chat:thinking → chat:stream → chat:tool → chat:tool-start → chat:tool-result`，每条事件经 `chat.go:persistBlock` 按 `blockSeq++` 单调递增落 message_blocks；前端 `ChatStreamDecoder.decodeStreamEvent` 按事件到达顺序同时维护：
- **旧字段**（兼容）：`streamingContent / streamingThinking / streamingTools / streamingSkill`
- **新字段**（真相源）：`streamingBlocks: StreamingBlock[]`，由 `chat/models/streamingBlocks.ts:applyBlockUpdate` 维护；同类连续合并（连续正文 delta 累计、连续 tool_result 按 tool_call_id 合并）。

前端组件：
- `MessageBlocksRenderer.vue` 同时接受 `ResolvedBlock[]`（历史）与 `StreamingBlock[]`（流式），按数组顺序渲染；text 块通过 slot 让外层接 MarkdownRenderer + 光标。
- **过程卡**：`renderGroups` 把**连续**的工具单元归入同一张 `.wb-trace` 卡（行间极浅分隔线 + 整行 hover），非工具块各自独立。所以「叙述 1 → 工具组 → 叙述 2」的分组天然正确；一屏十几个工具不再是一堆散行。
- `MessageItem.vue` 用 MessageBlocksRenderer 替代 TaskTimeline + MarkdownRenderer（历史消息）。
- `StreamingBubble.vue` 用 MessageBlocksRenderer 替代 TaskTimeline + MarkdownRenderer（流式期间）；光标挂在最后一条 text 块。

流式结束时 `finalizeStreamingMessage` 把 `streamingBlocks` 转为 MessageBlock 形状写入消息（chat:done 先于落库的窗口期兜底）。

**过程收起（手动，不自动折叠）**：历史 assistant 消息默认**展开**——正文与工具按真实顺序穿插渲染，与流式期间的观感完全一致。过程步数 ≥2 且消息有正文时，头部给一个「执行过程 · 收起过程」胶囊开关；用户点了才折成一行迹线（`执行过程 · 执行 4 条命令 · 读取 2 个文件 · 2s`，聚合复用 `toolGroupSummary.ts`），正文照常显示。

> 默认展开是刻意的：早期版本默认折叠，回复结束的瞬间「过程被拍扁成一行」会产生明显闪动，且回看的顺序与刚才流式看到的顺序不一致。**一致性优先于紧凑**，紧凑改为用户显式操作。简单回合（<2 步）不给开关；焦点模式只留正文；收起态下独立的「思考回看」行隐藏（思考已归入迹线）。

- 可靠性：`Last-Event-ID` 重放、内存环形缓冲被覆盖时下发 `chat:gap` 转全量快照、双看门狗（全静默 / 仅心跳）判定假死后指数退避重连、整轮总超时兜底。
- 终态：`chat:done` 在 assistant 消息落库**之后**发出，前端收到后拉权威快照；停止原因归一为 completed / cancelled / max_turns / stagnation / token_budget / error，可恢复终态给「继续」入口。

## 审批与后台任务

- 审批（durable pause）：工具策略门 ask → `chat:approval` 事件阻塞等待 → 前端三选一（批准 / 本会话允许 / 拒绝）→ `chat:approval-decided`。不可逆操作每次必问；未决请求落库，刷新与重启后经 `GET /chat/approvals/pending` 恢复（启动把遗留 pending 的决策窗口重武装 24h，不再作废）；**重启后决策（批准/拒绝/跳过/答复）落终态并自动从检查点续跑原 run**，续跑重放的同一调用按已决记录快速放行/拒绝（consumed 防重复免审）；同会话新 run 启动时清掉遗留挂起。补充输入（input_required）走 `/chat/approval/:id/answer`。
- 后台任务：`POST /tasks` 提交（有界 worker 池执行长任务），`GET /tasks`、`GET /tasks/:id`、`POST /tasks/:id/cancel`；任务中心实时显示进度与结果。

## 辅助对话（右栏并行小会话）

- 会话模型：`chat_sessions.kind = 'side'` + `parent_id` 指向主会话；侧栏列表（ListByUser / ListByUserPage）按 kind 过滤，辅助会话只存在于右栏辅助面板，一个主会话至多一个（`FindSideByParent`，Ensure 幂等：存在即复用）。模型 / 工作区 / 权限模式随主会话。
- 上下文继承：辅助会话每轮 run 在自己历史之前拼接主会话的**叙事纪要**（`sideParentMessages`，预算 12000 rune）——直接从消息行提取 user 提问与 assistant 结论（**含已归档轮次**，重度压缩后它们是结论的唯一完整来源；`<think>` 残段剥离，工具过程不进）；消息行被压缩裁空时回退到会话元数据的压缩归档摘要。首条 system 标注强约束「结合背景回答，不得声称没有历史」。
- 边界：不继承主会话的目标模式 / 待发送队列 / 后台任务；是功能完整的会话（可调工具、走审批，审批内联在面板内闭环）；面板关闭 / 主会话删除即不可达（会话与消息留存后端，不进侧栏也不可恢复入口）。
- 前端入口：header 辅助对话按钮（右栏第四 tab，宽 26rem）、`/side`（`/btw` 同义）命令、划选浮层「在辅助对话中提问」（引用块预填输入框）；空面板为启动页四卡——辅助对话可用；**审查卡**内置审查流（选 diff 源 → 预览 → 发起 AI 审查，审查过程即辅助对话）；**终端 / 浏览器卡**跳转对应右栏面板。

## 右栏工作面板（Git）

header 图标组接入工作面板 tab（与 workspace/changes/tasks/side 并列）：

- **Git**（`GitPanel.vue`）：三视图切换（`seg`）——
  - **变更**：暂存区 / 工作区两段拆行（M/A/D/R/C/U/? 徽标，重命名显示 `原路径 → 新路径`），行内暂存 / 取消暂存 / 丢弃；点文件就地展开 unified diff（复用主链路 DiffView）；提交框（Ctrl+Enter 提交 + stage_all）。
  - **历史**：提交列表分页（每次 +20）、可选「含所有分支」、`--decorate` 引用徽标；点开某次提交看元信息（hash / 作者 / 日期 / 正文 / 父提交 / 引用）+ 文件清单（状态 + 增删行数）→ 再点文件看该次提交内的单文件 diff。
  - **图谱**：`git log --graph --oneline --decorate --all` 的只读原文，等宽渲染。
  - 分支行：切换（可搜索）、新建并切换、删除（下拉列出可删分支，当前分支不出现也不再被后端接受）、ahead/behind、刷新。
  - 数据源 `/git/*`；工作区跟随会话绑定，绑定变化自动重载；切到某视图才拉该视图数据（图谱在大仓库上不便宜）。

## AI 审查（辅助对话审查流）

审查入口在辅助对话启动页：选 diff 源（未暂存=工作区 vs HEAD / 已暂存=暂存区 vs HEAD）→ 预览 diff（行数统计）→ 「发起 AI 审查」把 diff（>60K 字符截断）包进审查提示词（逐条问题：严重度/文件行号/说明/建议，末尾给「可以提交 / 需要修改」结论）发给辅助会话执行；模型可再调工具读文件核实。

## 上下文占用透视

`GET /chat/sessions/:id/usage/context` 返回分段占用：system（含记忆注入）/ 工具定义 / 历史消息，各段有 token 数与千分比；历史段优先取末条 assistant 的实测 input_tokens，拿不到则按字符估算并标注估算。分段口径与真实请求同一装配入口，保证「用户看到的占用」与「实际发送」一致。

## 压缩叙事（事件 → 时间线）

- auto 压缩器产出的六段交接纪要随 `CompressBoundary.Summary` 下发：runner 在压缩边界事件里附带 `AutoCompressor.LastSummary()`，`chat:compressed` 事件带 `summary` 字段（micro 确定性折叠无纪要则为空）。
- 前端 `compressionNotice = { removed, summary }` 驱动时间线分隔线：默认「上下文已压缩（N 条历史已折叠）」居中弱化行；有纪要时行尾出「查看折叠纪要」，点击展开逐行纪要卡（限高内滚）。通知在下次发送或切会话时清除。

## 不变量

- 同一会话同时只有一个活动 run；重复续跑返回明确错误。
- `(session_id, seq)` 语义唯一，工具结果与插话注入也走同一分配器。
- assistant(tool_calls) 与 tool 结果配对完整；回发上游前剥离孤儿 tool 与空 assistant 占位。
- 每轮 LLM 调用用量单独落 `token_usages`，消息上的用量是末轮汇总。
