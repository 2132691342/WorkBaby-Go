# 记忆系统

三层记忆，落点与生命周期各不相同：

| 层 | 载体 | 生命周期 |
|---|---|---|
| 短期 | 会话历史（chat_messages） | 上下文窗口，由聊天层的上下文重建与压缩负责（记忆层不重复实现滑窗） |
| 长期 | `MEMORY.md`（按会话） | 追加式增量沉淀，跨轮次保留 |
| 情景 | `memory_episodes` + FTS5 | 每次成型一条摘要 + 对话副本 |
| 语义 | `memory_facts` | `(subject, key)` 唯一，覆盖更新 |
| 程序 | `memory_procedures` | `name` 唯一，覆盖更新 + 成功/失败计数 |

## 落点约定

绑定工作区 → `<workspace>/.workbaby/memory/`；未绑定 → `{home}/memory/{sessionID}/MEMORY.md`。落点跟随会话工作区，与快照、沙箱同源。

## 形成（写）：双通道

run 结束后异步沉淀（独立超时，不阻塞回复），由能力在 `Capture` 通道触发；两条通道分工明确，互不重叠：

| 通道 | 触发方 | 是否人审 | 产出 |
|---|---|---|---|
| 确定性形成 | `capability.NewMemory` → `memory/formation.go` 打分 + 正则抽取 | 免审（直接落库） | 情景 / 语义 / 程序 + 长期记忆增量 |
| 模型抽取收件箱 | `capability.NewInbox` → `service.NewInboxExtractor`（strict-JSON） | 人审（`pending`） | 事实 / 程序 / 技能草稿候选 |

- **确定性通道**：不调 LLM：按触发条件（消息数量阈值、显式触发词、工具链成功等）评估是否成型，输出三类提案；负反馈（明确表达不喜欢）一票否决，避免把一次性否定当成习惯沉淀。**procedure promotion** 就在这条通道：一次 run 内 ≥3 次工具调用（`MULTI_STEP_SUCCESS`）即把工具链沉淀为程序记忆。
- **收件箱通道**：用本 run 的 provider/model 做一次严格 JSON 抽取（`facts` ≤3 / `procedures` ≤1 / `skills` ≤1），候选先落 `inbox_items` 待审；人工批准后按 kind 合入语义记忆 / 程序记忆 / 技能库，拒绝则归档。抽取失败静默跳过，不影响 run 主链路。
- 写入语义：情景追加并同步 FTS5（同事务）；语义与程序按唯一键覆盖更新，FTS 索引先删后插避免陈旧条目；长期记忆按会话追加增量文本。
- 模型也可主动写入：`memory_write` 工具（kind=long_term / fact）。

## 检索（读）

- **关键词检索**：FTS5（trigram 分词，中文可用），BM25 排序；查询不足 3 字符（trigram 最小窗口）时零命中，自动退化为子串扫描并按相关度重排（不按时间排序）。
- **融合召回**：跨三类统一召回，按分数融合，带时间衰减（越旧权重越低）与近重复合并，并设相关性下限（低于下限不注入，避免噪声）。
- **注入**：每轮 run 前，长期记忆尾部（上限 4000 rune）恒定注入；**跨会话召回**（默认 TopK 5）受 `RelevanceGate` 门控——显式 `@memory`/`@记忆`/`@recall` > 指向前文的关键词（「之前/上次/还记得…」）> 默认关闭，避免每轮都吃掉一块可能无关的 token；知识库自动召回同理（`@knowledge`/`@知识`/`@kb` + 资料类关键词），未放行时模型仍可主动 `knowledge_search`。

## 不变量

- 短期窗口不在此层实现：上下文重建只由聊天层负责，避免两套滑窗口径不一致。
- 情景写入与 FTS 索引同事务；覆盖更新不留陈旧索引。
- 召回有下限与时间衰减，不注入低相关噪声。
- 长期记忆落点随工作区，删会话不清空全局记忆文件。
- 收件箱去重键是 `(kind, title)`：同一候选重复抽取只留一条待审，不会堆积重复提案。
- 收件箱合入是有副作用的（写正式库），因此必须显式人审；确定性通道的噪声由打分阈值与负反馈一票否决兜住。
