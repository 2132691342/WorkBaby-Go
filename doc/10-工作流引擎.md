# 工作流引擎

位置：`internal/workflow/`（执行器与图模型）+ `internal/workflow/nodes/`（节点）+ `internal/service/workflow.go`（编排）。

## 模型

工作流是一个有向无环图（DAG）：

- 节点（Node）：七种类型，各自实现 `Run(ctx, input) (output, error)`。
- 边（Edge）：声明上游输出如何映射到下游输入；同一层的多个节点并行执行。
- 入参：工作流可声明输入参数，触发时传入。

## 节点类型

| 节点 | 行为 |
|---|---|
| `llm` | LLM 调用；配置了 tools 时走 ReAct 多轮工具循环（与聊天同一主循环），用量统一计量 |
| `tool` | 直接调用某个工具 |
| `code` | 沙箱内执行 JavaScript（goja）做数据变换 |
| `condition` | 按表达式路由到不同分支 |
| `http` | 调外部 HTTP 接口（默认 30s 超时） |
| `human_input` | 暂停等待人工输入（审批式交互） |
| `channel` | 经通知通道发送消息 |

## 执行语义

```
run → 拓扑分层 → 逐层执行（同层并行）→ 节点结果持久化 → 下一层
暂停点：human_input 节点 → 执行态 pending，等待 input 接口回填后 resume
中断：cancel 立即停止调度，已完成节点结果保留，可从断点 resume
```

- 每个节点的输入输出、耗时、错误都落 `workflow_node_executions`，执行详情页可逐节点查看。
- 执行态：`running` / `paused` / `completed` / `failed` / `cancelled`。
- 事件经 `workflow:*` 前缀桥接到 SSE，前端实时看节点状态。

## 图校验与编辑

保存前校验（`/workflows/validate`）：环检测、孤立节点、边的输入映射合法性、节点参数完整性。前端用 Vue Flow 提供可视化编辑器，节点类型清单由后端下发（`/workflows/node-types`），前后端不重复维护。

## 触发方式

1. 对话中模型调用 `run_workflow` 工具。
2. 用户在工作流页手动运行。
3. 定时任务按 cron 触发（见 11）。

所有入口共用同一个执行器与执行记录，仪表盘可统计执行次数与成功率。
