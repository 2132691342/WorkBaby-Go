# 14 · 前端架构与 UI 设计

Vue 3 + TypeScript + Vite + Element Plus + Pinia 前端工程。
双主机架构：前端经 fetch + SSE 与后端 gin 通信；UI 采用「Studio 桌面工作台」视觉体系。

---

## 1. 双主机前端

```
Vue3 前端（WebView2 渲染）
  │
  ├─ fetch      ──► http://127.0.0.1:{serverPort}/api/v1/**      REST（GET/POST）
  ├─ EventSource ─► http://127.0.0.1:{serverPort}/api/v1/events   SSE 流式/推送
  ├─ Wails runtime ─► 系统能力：文件对话框 / 剪贴板 / 托盘
  └─ <img src="/files/..."> ──► Wails AssetServer 静态资源（媒体/sprite/工作区）
```

**端口发现与基址（防 404 关键）**：`app:ready(serverPort)` 注入后，`http.ts` 的 origin = `http://127.0.0.1:{port}`；
调用路径**自带 `/api/v1`**。`getApiBase()` 供 SSE 使用。**禁止** origin 再拼 `/api/v1`（否则产生 `/api/v1/api/v1/...` 404）。

**静态资源**：媒体 `/files/media/{id}`、sprite `/files/sprites/{id}`、托管文件 `/files/files/{id}`、工作区 `/files/workspace/{sessionId}?path=`。这些走 AssetServer，**不是**业务 API。

## 2. 目录

```
frontend/src/src/
├── api/                      # HTTP 封装层（唯一直接 fetch 的地方）

│   ├── bootstrap.ts          #   app:ready 端口注入（localStorage 兜底）
│   └── stream.ts             #   SSE 流式订阅（mapSSEEvent 归一化 + lastEventId 重放 + watchdog）

├── i18n/                     # dict-zh / dict-en（自研轻量 i18n）

├── utils/                    # error / time / format
├── chat/                     # chat/models 纯函数（块解析 + diff 识别）+ chat/composables
├── composables/              # useShortcuts / useCommandPalette / useWbChartTheme / useTheme

```

## 3. HTTP API 封装层

```ts
export async function apiGet<T>(path: string): Promise<T> { return request<T>(path, 'GET') }
export async function apiPost<T>(path: string, body?: unknown): Promise<T> { return request<T>(path, 'POST', body) }
```

- 统一解包 `{code, message, data}`：`code=0` 返回 `data`；非 0 抛 `Error(message)`；
- 非 JSON 响应（404 HTML）给出 `[status] METHOD path` 以便定位契约漂移；
- 组件不直接 fetch，一律经 store → api 层。

## 4. 流式消息渲染

- `mapSSEEvent`：SSE 事件名 → 前端事件（纯函数）；
- rAF 批刷新：流式高频 delta 合并渲染，避免卡顿；
- 终态防御：空 streamingMessageId / 末条是 user / 内容已清空 / 占位消息——任何异常路径不停在「正在输入」；
- 上下文占用：`ctxUsed = 末条 assistant.input_tokens / provider.context_window`，done 后权威值覆盖。

## 5. UI 设计体系（Studio 工作台）

### 5.1 设计理念

| 原则 | 落地 |
|---|---|
| 桌面工具感 | 紧凑密度、克制阴影、清晰层级，接近 VSCode / Notion / Raycast |
| 单品牌色 | 全站唯一主色（靛蓝），只用于交互态与关键强调 |
| 中性灰阶分层 | bg → surface → surface-2 → hover，靠明度建立层级 |
| 1px 细节 | 细边框 + 6–10px 圆角 + 阴影仅在浮层 |
| 排版即结构 | 字号/字重/行距承担信息层级，颜色留给状态 |

### 5.2 设计 Token（themes.css 为准）

```
--wb-bg / --wb-surface / --wb-surface-2 / --wb-surface-hover  表面分层
--wb-border / --wb-border-strong                              描边
--wb-ink / --wb-muted                                         文本
--wb-primary / --wb-primary-strong / --wb-primary-soft        品牌色
--wb-success / --wb-warning / --wb-danger / --wb-info          语义色
--wb-mint / --wb-lavender / --wb-sky / --wb-lemon              点缀色
--wb-radius-sm/base/lg   6 / 8 / 12px
--wb-shadow / --wb-shadow-lg / --wb-shadow-pop                 阴影
--font-sans / --font-display / --font-mono                     字体栈
```

- Tailwind 4 `@theme` 注册 token 生成 utility（`bg-wb-primary`），`:root`/`[data-theme]` 同步 `--wb-*`；
- **禁止硬编码颜色**：新增颜色必须先定义 token。

### 5.3 主题

- `light`（暖纸白底）/ `dark`（深炭底）两套；`useTheme.setTheme` 唯一入口；
- `data-theme` 挂 `html`，CSS 变量驱动，无硬编码；
- Element Plus 变量在 `themes.css` 尾部桥接（`--el-color-primary` 等）。

### 5.4 组件基元（style.css `@layer components`）

| 组件 | 规范 |
|---|---|
| Button | `btn-primary` / `btn-secondary`（白底细边）/ `btn-ghost` / `btn-danger` / `btn-icon` |
| Card | `.card`（surface + 细边 + 轻阴影）/ `.card-2` / `.card-pop` |
| Input | `.input` / `.input-xs`：1px 边框 + focus 主色 + 3px 16% 光环 |
| Badge | `.badge-*`：语义色 12% 底 + rounded-full |
| 弹层 | `el-dialog/drawer/popper` 统一 14px 圆角 + 1px 描边 + `--wb-shadow-pop` |

### 5.5 动效

- 只保留状态切换 / 消息进入 / hover 反馈三类；曲线 `cubic-bezier(.16,1,.3,1)`，150–350ms；
- `prefers-reduced-motion` 下全部禁用。

### 5.6 字体

- UI 无衬线：Inter（内置 otf）+ 中文系统栈；
- Display 标题：Georgia / 宋体栈（克制用于 Hero 与文档标题）；
- 代码：JetBrains Mono / Fira Code / Cascadia Code / Source Code Pro 等内置字体；
- 不引外部字体下载（体积 / 版权）。

## 6. 国际化

- 自研轻量 i18n（`src/i18n/`），`zh-CN` 默认，`en-US` 可选；
- 所有 UI 文案走 key，禁止硬编码。

## 7. 页面与视觉要点

| 页面 | 视觉要点 |
|---|---|
| 仪表盘 | 统计卡 + token 三线折线（今日 24h / 近 7 天 / 本月 / 自定义）+ 趋势柱图 + 最近动态 |
| 聊天 | 侧栏会话 + 消息流 + 可选工作区面板；顶部统一紧凑 chip（模型/工作区/权限/参数）+ 上下文指示器；空态一键示例 prompt |
| 工作流 | Vue Flow 画布：调色板/属性面板由 node-types 目录驱动（schema 表单），condition 双出口，运行态画布高亮 |
| 知识库 | hero 头 + 表格列表 + 检索/分组/重试 |
| 记忆 | hero 头 + 召回卡 + 三类 tab |
| 设置 | tab 导航 + 分节卡片（基本信息/连接/行为…），全站统一 hero 头 + `.card` 分区模式 |
| 桌宠 | 同窗形态切换（PetDesktop） |

**全站一致性**：14 个页面统一「hero 图标头 + `.card` 分区」；`.wb-el-table`/`.wb-el-form` 主题在 `style.css` 全局唯一声明（禁止各视图复制 scoped 副本）；主题相关色一律 wb token，硬编码色仅限白名单（彩色按钮白字 / 图片遮罩 / GenUI `.wb-genui` 重映射域）。

## 8. 交互能力

| 能力 | 落地 |
|---|---|
| 命令面板 | `components/common/CommandPalette.vue` + `composables/useCommandPalette.ts`：Ctrl+K / Ctrl+Shift+P 呼出；全站导航 + 新建会话 / 清空消息；子序列模糊匹配；键盘 ↑↓/Enter/Esc。命令注册协议收口在 composable。 |
| SSE 可靠性 | `api/stream.ts` 维护 lastEventId + watchdog（75s）+ 指数退避重连（500ms~8s）+ `chat:gap` 快照刷新。SSE 端点 /api/v1/events 由后端 server/sse.go 提供。 |
| 工具过程增强 | TaskTimeline：单工具复制 / 展开收起全部 / unified diff 着色（`chat/models/blocks.ts` 纯函数）/ 末条失败工具重试（转 resendFrom） |
| 长会话滚动 | `content-visibility: auto` + `contain-intrinsic-size: auto 96px`（Chromium 记忆实际高度，消除滚动跳动） |
| 图表 token 通道 | `composables/useWbChartTheme.ts`：CSS 变量 → 具体颜色（`withAlpha` 兼容 hex/rgba），随主题重算。Dashboard 双图（三线/柱状）与 Hero 渐变、sparkline 全部摘除 `isDark ? '#xxx' : '#yyy'` 硬编码 |
| 工作流边色 | `WorkflowGraphView` 节点色板 → CSS 变量字符串（`var(--wb-*)` + `color-mix` 混色区分 human_input/channel），Vue Flow DOM 样式随主题即时生效 |
| 空状态插画 | `EmptyState.vue`：语义色（错误→danger token、工作流→lemon token）与结构性白色填充（气泡/云朵→surface）token 化；角色贴纸色为跨主题品牌常量，保留固定 |
| 审批内联 | 审批卡从 `ChatView` 顶部下移 `MessageList`（`ApprovalInline.vue`），贴近触发它的运行消息，长会话不再悬浮割裂 |
| 运行态常驻 | `ChatView` header 状态点按 `streaming` 切换：执行中主色脉动（`animate-ping`），空闲静点；同处常驻停止按钮（`Square` 图标 + 红色 type），复用 `chat.cancelStream()` 链路 |
| 变更未读 | `ChatView` 变更按钮包 `el-badge`：会话写入 `file_changes` 数实时计数，面板打开后自动隐藏，角标偏移 `[2,6]` |
| `<think>` 剥离 | `chat/models/blocks.ts::stripThinkBlocks`：兼容端点把推理写进正文用 `<think>` 包裹，闭合块全局剥离、流式中未闭合尾部一并剥离；渲染层（MarkdownRenderer）兜底，避免原始标签闪现 |

## 9. 落地约束

- 样式集中在 `style.css` / `themes.css`，组件内不写散落魔数颜色；
- 前端 API 路径、字段与后端严格一致（防 404 清单见 API 契约总表文档）；
- UI 重构不改变双主机接口契约。
